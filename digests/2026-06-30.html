本期一句话 · TL;DR

Vol.026 说建造变廉价、品味变稀缺;这卷把视线移到价值链两端,发现它们正同时『去人化』。供给侧:GLM-5.2 证明开源权重已到生产级——$3.36 跑完 45 分钟自主编码,选型从『能力天花板』变成『成本/控制/供应商依赖』,你赖以构建的模型正在商品化、可路由。需求侧:AI agent 开始替人比价下单,最前沿公司已给机器单发一份 .md 定价页——你服务的『读者』正在变成机器。两端的人本假设同时松动,价值往哪挪?

带着这 3 个问题读 · 思考题

  1. 如果你赖以构建的模型在 12 个月内变成可随时替换的商品(开源权重摸到 Opus 级、成本低一个数量级),你今天的技术栈里有多少是把模型供应商硬编码进去、换一家就要改应用代码的?你的『对冲』是真能执行,还是 PPT 上的一句话?
  2. 当推荐你产品的越来越是 agent 而非人,你最关键的对外页面(定价/文档/政策)在被机器读取时还剩多少准确信息?你有没有任何指标在监测『AI 搜索/推荐里我们排第几、被怎么描述』——还是这部分获客正悄悄发生在你的 analytics 之外?
  3. benchmark 越接近,你越要靠它测不到的东西做决定(GLM 在 SWE Bench 逼近 Opus,却在你的真实 React 工况里更不稳)。你团队现在是拿跑分做选型,还是拿『它在我们自己的真实工况里稳不稳』做选型?

LENNY'S / HOW I AI · 开源到达生产级

GLM-5.2 实测:开源权重做到 Opus 级编码,$3.36 跑完 45 分钟自主任务——选型从『能力天花板』变成『成本/控制/供应商依赖』

Lenny's Newsletter · How I AI(Claire Vo — GLM-5.2 live review in a real codebase) · 原文
信号 ●● · 颠覆 ●● · 可操作 ●● · 独特 ●○ · 时效 ●● · 9/10
开源权重模型已跨过『生产级』门槛——GLM-5.2(北京 Z.ai)在真实 codebase 里做到 Opus 级编码,$3.36 跑完一段 600 万 token、45 分钟的自主 bug 猎杀任务,还揪出两个人工监控漏掉的 P0。选型问题从『能力天花板』彻底变成『成本、控制、供应商依赖』。
承重论据 · 为什么成立

开源权重不再是爱好者玩具,而是生产级替代品。

GLM-5.2 在 SWE Bench Pro 上逼近 Claude Opus 4.8、超过 GPT-5.5,百万 token 上下文,完整支持 reasoning / function calling / structured output / context caching。Claire 在自己 ChatPRD 的真实 codebase 上跑代码审计、UI 重设计、以及一段 45 分钟的自主任务——不是 demo,是把它放进真实关键路径上压测。她一句定性:『this is not a toy.』

自托管/开源权重把供应商权力关系整个翻转。

open-weight 意味着训练权重公开,团队可在自有硬件推理、用私有数据 fine-tune、绕开任一 provider 的 API 条款。前沿厂商一改价改策,用开源权重的团队换个 inference provider 即可,不动一行应用代码——『你没被锁死』。这正面接续 Vol.025『把用得上的主动权抢回来』:那卷是姿态,这卷是可量化的工程现实。

成本曲线结构性不同,长 agent 会话越跑越省;但具体工况仍要逐个压测。

$3.36 / 600 万 token(含整段 45 分钟自主任务),72% cache 命中助力,但即便全价,Open Router 上的开源推理也远低于 Opus / GPT-5.5。对累积长上下文的 agent(前沿模型成本复利最快的工况),这是结构性更优的曲线。代价:React 在多步 agentic 压力下不稳(Claire 估自己 98% 工况是 React),HTML/CSS 才靠谱。她的建议是『put it in rotation, not in the spotlight』。

一个张力 · 它没说的
张力在于:『生产级』这词被一排跑分撑着,但 Claire 最诚实的那句是『React under agentic pressure is shakier』——而她 98% 的工况恰恰是 React。换句话说,开源权重在『模型能不能做』上追平了,却在『你这套具体工况稳不稳』上仍要逐个压测;benchmark 越接近,真正的决策权越落回到那条 benchmark 测不到的可靠性曲线上。这与今日 No Priors 那条短评互为镜像——他们直言『能力=你投进多少 test-time compute 预算』,该按哪个预算评估,现有 policy 根本没回答;两边指向同一句话:跑分早就不告诉你它自以为告诉你的事了。
对 TikTok Gaming 意味着什么
对 TikTok Gaming,GLM-5.2 把 Vol.025『开源自托管是战略对冲』从一句姿态推成了可量化的工程决策:当开源权重在编码上摸到 Opus 级、成本低一个数量级,问题不再是『敢不敢用开源』,而是『哪些工作流的成本/控制收益大到值得迁移、哪些工况(如重 React 链路)必须先压测才敢上』。具体两条:第一,把『模型供应商』当可替换组件来设计你的 agent 基础设施——把 API key 路由层(如 Open Router)、base URL、模型名做成配置而非硬编码,这样换模型不动应用代码,这才是真正可执行的对冲,而不是一句口号。第二,别被跑分骗着一把梭——迁移前用你自己的真实 codebase 跑一个长时自主任务(像 Claire 那样拉 72 小时 Sentry + Vercel 日志做优先级修复计划),用『它在你的工况里稳不稳』而非『它在 SWE Bench 上多少分』来做最终决定。
值得记住的原话

“The decision is no longer about capability ceilings but, instead, about cost, control, and vendor dependency.”

决策不再关乎能力天花板,而关乎成本、控制与供应商依赖。

“$3.36 for 6 million tokens, including the full 45-minute agentic session.”

600 万 token 只花 3.36 美元——含整段 45 分钟自主任务。

TOM'S MARKETING IDEAS · 给机器写的界面

大家都在给机器人写定价页:当 AI agent 成了买家,最前沿的公司开始给机器单发一份 .md 定价

Tom's Marketing Ideas(Everyone is writing a pricing page for robots) · 原文
信号 ●● · 颠覆 ●● · 可操作 ●● · 独特 ●● · 时效 ●● · 10/10
AI agent 正在成为真实买家——它们替人比价、甚至直接下单,而你的页面是给人眼写的;最前沿的公司已经开始给机器单独发一份机器可读的 pricing(.md 文件),因为『能不能被 agent 读懂并推荐』正在变成新的获客入口。
承重论据 · 为什么成立

购买决策正在前移到 agent,且发生在你的 analytics 之外。

买家在 ChatGPT 里问『X 品类最便宜的工具』,AI 查几个 pricing page 选个赢家、有时直接买下;竞品被推荐、你没有,而这一切都不进你的流量分析。文中那段 HubSpot 广告本身就是证据——市场上已经长出一个新品类:『在 AI 搜索里你的品牌排第几、竞品有没有取代你』。

机器读你的 pricing page,通常只读到代码里埋着的价格、或啥都读不到。

人眼页面对机器是噪声。解法是复制一份机器能读的 pricing:Buffer 在常规套餐下放一行『See machine-readable pricing (for AI agents)』,点开是 .md 纯文本,且比网页更详尽——把分级量价做成干净表格,机器能读出 1 / 10 / 50 channels 的确切月费。

这是一套正在成形的『给 agent 的接口规范』,不止价格。

Flowdown 给机器发多个文件(pricing.md + docs + 一条『区域 App Store 价格为准』的提示),省得 agent 报错价;Resend 用『Are you an AI agent?』的措辞专门招呼机器。网站正在长出一层 machine-native 的平行界面——人看一版、agent 读另一版,后者是结构化、无歧义、为『被正确引用』而优化的。

一个张力 · 它没说的
张力在于:这看起来是个小聪明的 marketing trick,实则是 Vol.026『taste / curation』的需求侧续集——但它把一个尴尬问题摆上台面:当推荐你的是 agent 而非人,你优化的对象从『打动人的叙事』变成『让机器无歧义地引用』,这两者经常打架(对人要故事和情绪,对机器要表格和确定性)。而且一旦大家都发 .md,这层很快会变成新的 SEO 军备竞赛——agent 凭什么信你那份 .md?可验证性、第一方数据、甚至给 agent 的『可信源』认证,会是下一个战场,而它目前完全无标准、无问责,正像 Vol.025 那套『临时 AI 许可制度』的商业镜像。
对 TikTok Gaming 意味着什么
对 TikTok Gaming,这条提示一个容易被忽略的渠道转移:当用户(尤其开发者、广告主、公会运营)越来越多地用 AI agent 来调研『哪个平台/工具/变现方案最划算』,你的产品文档、价格、分成政策能不能被 agent 准确读取和引用,正在变成一个真实的获客/留存变量,而且它不出现在现有漏斗分析里。具体两条:第一,审计你面向外部的关键页面(开发者文档、变现/分成政策、API 定价)在『被机器读取』时还剩多少信息——把核心事实做成结构化、无歧义、第一方可信的机器可读版本,而不是把价格埋在 JS 渲染的组件里。第二,开始把『在 AI 搜索/推荐里我们排第几、被怎么描述』当成一个要监测的指标,因为这部分决策正发生在你的 analytics 之外;早一步建立监测,就早一步知道竞品在 agent 眼里是不是正取代你。
值得记住的原话

“Your pricing page is probably built for human eyes. When a robot reads it, it usually gets a pile of code with the price buried inside, or nothing at all.”

你的定价页多半是给人眼写的;机器来读,通常只看到一堆代码里埋着的价格,或者啥都没有。

“See machine-readable pricing (for AI agents).”

查看机器可读定价(供 AI agent 使用)。
