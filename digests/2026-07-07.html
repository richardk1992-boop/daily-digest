The Judgment Premium — 当生成近乎免费:模型质量在商品化,稀缺的变成 taste 与管理——把品味固化成可复现 benchmark,把自己从 agent prompter 变成 agent manager

本期一句话 · TL;DR

Vol.033 走进 agent-native 组织内部,看到价值从『生产』移向『判断与综合上下文』;Vol.034 用两档 How I AI 播客给这条判断补两个可操作落点。其一(Claire 的 Sonnet 5 评测):当模型质量开始商品化——Sonnet 5 被定在接近老 Sonnet 的便宜中间带、并不自动替代谁——稀缺、可防御的能力从『生成』移到『评估』;她跑 64 次盲测发现 LLM-as-judge 太宽容、往量表中间聚,人的 taste 在第一眼截图就抓到被判官漏掉的坏原型;让 benchmark 真正有意义的是可复现(冻结输入、固定 rubric),而非一次性 vibe check。其二(Alessio 从手机管理自主 agent):真正的解锁是从『agent prompter』变成『agent manager』——按任务记 token 账、定期精简 skills 文件、用 Linear 当异步状态机、给 agent 更好的感官。合起来:当生成变便宜,瓶颈移到评估与管理,而把你的品味和积累的上下文固化下来,才是护城河。折扣:样本是极度 AI-forward 的 builder,单人 taste、模型迭代快导致快照易过时。

带着这 3 个问题读 · 思考题

  1. 你团队现在判断一个模型/agent 产出好不好,靠的是一次性 vibe check 还是可复现的 benchmark?如果明天换个模型上来,你能不能用冻结输入 + 固定 rubric,在半天内给出跨模型可比的结论——还是又得重新拍一次脑袋?
  2. 把你用 agent 的姿态诚实标一下:你还在当『prompter』(逐条敲提示、盯着它做),还是已经在当『manager』(按任务记 token 账、精简 spec、用看板把异步任务当状态机)?阻碍你转成 manager 的,到底是工具不行,还是你还没把它当下属来管?
  3. Claire 发现自动评测的排序和她的 taste 几乎完全相反,而她认为自己(至少部分)是对的。回看你自己:你有没有把『我到底在乎什么』一条条写进评测标准?如果没有,你凭什么相信任何自动打出来的分数——包括你让另一个模型当 judge 打的?

PODCAST · eval & agent-mgmt

How I AI:Sonnet 5 盲测 + 从手机管理自主 agent——当模型商品化,稀缺的是 taste 与管理

Lenny's Podcast Network《How I AI》双集(主持人 Claire Vo)——第一集是 Claire 亲手搭 benchmark、盲测 Sonnet 5;第二集嘉宾为 Kernel Labs 创始人、Latent Space 联合主持人 Alessio Fanelli,讲从手机管理自主 coding agent · 原文
信号 ●● · 颠覆 ●○ · 可操作 ●● · 独特 ●○ · 时效 ●● · 8/10
如果 Vol.033 的结论是『当 build 成本趋近于零,价值从生产移向判断与综合上下文』,那这两集 How I AI 就是把这条抽象判断落成两个可操作的姿势。第一集里 Claire 做了一件反直觉的事:面对刚发布、定价便宜的 Sonnet 5,她不看榜单,而是跑 64 次盲测、亲手搭一个可复现的个人 benchmark,结论是模型质量正在商品化、真正稀缺的是『可靠地评估好坏』的能力,而且人的 taste 依然打得过 LLM-as-judge。第二集里 Alessio 给出另一半:当你真的大规模委派,身份就得从『agent prompter』变成『agent manager』——记账、精简 spec、把异步任务当状态机管。两集合起来指向同一件事:generation 越便宜,评估与管理越贵。
承重论据 · 为什么成立

模型质量在商品化:选型不再看榜单排名,而看『在我的任务上到底好不好』——稀缺性从生成移向评估。

Claire 指出 Sonnet 5 被定在一个耐人寻味的中间带——夏末前 $2/百万 input、$10/百万 output,价格贴近老 Sonnet 而非 Opus,但『它并不自动替代其中任何一个』。在她的盲测里 Sonnet 5 排在个人偏好榜的靠后位置,于是她的结论是:『成本论点只有在质量论点对你的具体用例也成立时才成立。』这背后的机制很清楚:当一批模型能力趋同、价格集体下探,单看 leaderboard 的名次已经没法指导选型——你需要的是一套能在你自己的任务上区分好坏的评估手段。她甚至给出按任务的建议(PRD 用 GPT-5.5、原型和闲聊用 Sonnet 4.6、代码库导航用 Opus 4.8 或 Sonnet 5),但这些结论本身是她跑完 benchmark 才得到的,而不是从发布博客里读来的。

LLM-as-judge 太宽容、往量表中间聚;人的 taste 在第一眼就抓到判官漏掉的东西;而可复现才让 benchmark 真正 matter。

Claire 让 GPT-5.5 和 Opus 4.8 分别给 64 个产出当 judge,两个都不够 spiky、评分都往量表中间挤,漏掉了她一眼(第一张截图)就看到的坏原型和被忽略的 wireframe 约束——她的原话是『模型还看不到人眼在第一次视觉扫过时就抓到的东西』。更尖锐的是:LLM judges 把 Gemini 3 Pro 排最高、Sonnet 4.6 排最低,而她的 taste 排序几乎完全相反;当她用 70/30(她 7、模型 3)加权,Sonnet 4.6 直接跳到第一。这个分歧告诉她 rubric 还没把她真正在乎的东西编码进去。而让这一切能积累的前提,是她反复强调的可复现:『一次性 vibe check 感觉有用,但不可复现——正是可复现让 benchmark 真正有意义』,靠的是冻结输入、固定 rubric、每次新模型上来都跑同一批任务。她还点出一个几乎人人闲置的资产:Claude Code / Codex 能读你桌面上旧的 session 历史,基于你真实做过的工作来生成评测任务。

从『agent prompter』到『agent manager』:delegation 一旦规模化,人的活就变成管理——记账、精简 spec、把异步任务当状态机。

第二集里 Alessio(Kernel Labs)从手机用 OpenAI Symphony + Linear + 云 VPS 管理自主 coding agent,他说最大的、多数人还没抓住的解锁,就是身份从『提示者』变成『管理者』:早期 agentic 流程在第二三次介入时就被本地 runtime 的摩擦拖垮,搬到云 VPS + 多通道(Linear / shell / 手机)之后,真正的异步管理才成立。三个 manager 级 primitive 很具体:① 按任务记 token 账——他展示的任务从 1500 万到 2.21 亿 token 不等,没有这本账就没有改进 spec 的反馈回路;② 每隔几个月精简 skills 文件——模型倾向于往里加指令而不是替换,文件越长越会自相矛盾,所以要短、紧、明确;③ Claire 补的祛魅:Symphony 不是魔法,只是一份『很有主见的 Markdown spec』告诉模型怎么行动,复杂 agent 编排的吓人框架说到底就是一个 Markdown 文件。这正是 Vol.033『PM 从写文档的人变成设护栏的人』在个人工作流层面的镜像。

一个张力 · 它没说的
样本高度偏斜。Claire 和 Alessio 都是极度 AI-forward 的 builder / 创作者,他们喊出的『taste 是护城河』既是洞见,也可能是屁股决定脑袋——人在被替代焦虑下天然会抬高『人的判断』的价值。要打几个具体的折:其一,Claire 的 taste 是 n=1 的个人偏好,她自己都承认 rubric 还没把在乎的东西编码进去、benchmark 只是 v1、还很粗,所以把她的模型排序(Sonnet 4.6 第一)直接当选型建议是危险的——那是她的口味不是普适结论。其二,模型迭代极快,任何『Sonnet 5 值不值』的快照几周就过时,这条的时效性天然打折。其三,Alessio 的 token 账、skills 精简明显偏重度工程用户,普通团队未必有那么多自主 agent 要管。但把这些剥掉,内核和 Vol.033 完全同构且更可操作:当生成趋近免费,瓶颈就从『产出』移到『评估 + 管理』,而评估和管理恰恰是能刻意建设的资产(可复现的 benchmark、token 账本、精简的 spec)。方向确定,速度取决于你愿不愿意把品味写下来。
对 TikTok Gaming 意味着什么
对 TikTok Gaming,这两集把 Vol.033 那个抽象命题落成三个能立刻做的动作。第一,给你们最常用的一两个 agent 任务搭一个『可复现评测台』:冻结几组真实输入,写一份固定 rubric——把你们真正在乎的东西逐条写进去(美术一致性、玩法手感、文案调性、本地化准确度),每次有新模型就盲测同一批。别再用一次性 vibe check 拍脑袋选型,也别全信 LLM-as-judge 打的分——它太宽容、会漏掉你一眼就能看到的破绽,人的 taste 仍是最锋利的第一道筛。第二,把团队里重度用 agent 的人从『prompter』往『manager』推:要求按任务记 token 成本(这是唯一能让你回头改 spec 的反馈回路)、定期精简各自的 skills / 规则文件(别让它越堆越自相矛盾)、用一个看板(Linear / Meego)把异步 agent 任务当状态机来管。第三,把『积累的上下文 + 写下来的品味』当资产经营:让 agent 读你们过去的 session、工单、评审历史来生成贴合真实工作的评测任务和 spec——这份上下文大多数团队都闲置着,而它恰恰是竞品抄不走的护城河。
值得记住的原话

“One-off vibe checks feel useful, but they're not repeatable — and repeatability is what makes a benchmark actually matter.”

一次性的 vibe check 感觉有用,但它们不可复现——而正是可复现,让一个 benchmark 真正有意义。

“The shift from 'agent prompter' to 'agent manager' is the unlock most people are still missing.”

从『agent 提示者』到『agent 管理者』的转变,是大多数人到现在还没抓住的那个解锁点。
