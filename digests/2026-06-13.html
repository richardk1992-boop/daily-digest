EDITORIAL · 编辑卷首语

今天整个圈子在同一件事上撞了车,撞得干脆利落:不要再 prompt agent 了,去设计 prompt agent 的『循环(loop)』。Peter Steinberger 说『你应该设计驱动 agent 的循环』,Anthropic 的 Boris Cherny 说『我不再 prompt Claude,我写循环、循环干活』,Karpathy 说『把自己从瓶颈位置移走、最大化 token 吞吐——我不想做守在循环里盯结果的人』。三个人各自独立喊出同一句话,这种『独立同频』本身就是最强的信号。AINews 据此把它提炼成 agent 时代的『Salty Lesson(苦涩教训)』,对位 Rich Sutton 给模型的『Bitter Lesson』:别再像过去那样自己动手修一个个问题,转去做能随 agent 数量扩展的系统——目标(goals)与编排(orchestration)。而循环设计的核心手艺,是知道何时『下沉一层求可靠』、何时『上升一层求杠杆』。

论点 01

Steipete: "Here's your monthly reminder that you shouldn't be prompting coding agents anymore. You should be designing loops that prompt your agents." Boris: "I don't prompt Claude anymore. I write loops, the loops do the work."
Steipete:「这是给你的每月提醒:你不应该再去 prompt 编码 agent 了,你应该去设计那些 prompt 你的 agent 的循环。」Boris(Cherny):「我不再 prompt Claude 了,我写循环,循环来干活。」
MIRA · 批注
MIRA · 批注:这是本卷的定盘星,也是 Vol.012『意图不可训练』的直接操作化续集。Vol.012 说模型负责执行、意图留给人;本卷回答『那人到底该干什么』——人的活从『写 prompt(在循环里)』上移到『设计循环(在循环外)』。两位是 Peter Steinberger 与 Anthropic 的 Boris Cherny,各自独立喊出同一句话,这种『独立同频』本身就是强信号:prompt 工程作为核心技能正在被『循环设计/编排』取代。给 Gaming 的判断:衡量团队 AI 成熟度的指标要从『谁的 prompt 写得好』迁到『谁设计的循环跑得稳、能无人值守扩展』。把『循环设计能力』当作新的一等工程技能来识别和培养。

论点 02

Karpathy on autoresearch: "You have to remove yourself as the bottleneck. You can't be there to prompt the next thing... the name of the game now is to increase your leverage. I don't want to be the researcher in the loop looking at results etc, I'm holding the system back. So the question is how do I refactor all the abstractions so that I'm not — I have to arrange it once and hit go."
Karpathy 谈自动化研究:「你必须把自己从瓶颈位置移走。你不能守在那里去 prompt 下一件事……现在游戏的名字叫提升你的杠杆。我不想做那个守在循环里盯结果的研究员,我在拖慢系统。所以问题是:我如何重构所有抽象,让我不必在场——我只需安排一次,然后按下开始。」
MIRA · 批注
MIRA · 批注:Karpathy 把『把自己移出循环』说成了一种纪律——只要你还守在循环里逐步 prompt,你就是系统的瓶颈。注意他的关键动作是『重构抽象,使得安排一次即可 hit go』,这与 Vol.011『委派+验收』、Vol.012 Kieran『隔夜跑、CI 绿自动 merge』是同一条演化线的源头理论。给 Gaming 的务实分寸:『把人移出循环』追求的是 token 吞吐/杠杆最大化,但前提是验收能被自动化(见 Vol.012 自动验收门)。在可自动验证的环节(构建、测试、数据处理、批量素材生成)激进地把人移出循环;在不可验证的环节(玩法手感、数值、品味)人仍是循环的必要一环。先问『这个循环的验收能不能自动化』,再决定人留不留在里面。

论点 03

"One might argue the entire game of the next century is to be able to stack loops as effectively as possible. In the early days of each phase, it will be valuable to know when to go DOWN a loop when things go wrong (for reliability)... but it will probably be more valuable to know how to go UP a loop as models improve (for leverage). If you don't figure out how to do this, don't be salty when you lose to those that do."
「也许可以说,未来一个世纪整个游戏就是:尽可能高效地堆叠循环。在每个阶段的早期,知道何时『下沉一层循环』(出问题时,为了可靠性)很有价值……但随着模型变强,知道如何『上升一层循环』(为了杠杆)可能更有价值。如果你想不明白怎么做,等你输给那些想明白的人时,别不服气(don't be salty)。」
MIRA · 批注
MIRA · 批注:这条给出了循环设计的核心操作变量——『上/下一层』的时机判断。下沉(go DOWN)= 出问题时回到更细粒度、人更介入的循环,换可靠性;上升(go UP)= 模型变强后退到更高抽象、更少介入的循环,换杠杆。这其实是一种动态的『信任校准』:不是一次性决定自动化程度,而是随模型能力、随任务可靠性持续上下调档。给 Gaming 的框架:为每条 AI 管线显式定义它的『循环层级阶梯』和升降档触发条件——比如『连续 N 次自动验收通过 → 上升一层(减少人工 checkpoint)』『出现 M 次回归 → 下沉一层(加回人工 review)』。把自动化程度做成可调档、有触发条件的旋钮,而不是拍脑袋的开关。

论点 04

The 'Salty Lesson' for agents (vs Sutton's 'Bitter Lesson' for models): "Don't fix things yourself, as you have done historically. Instead focus on systems that scale with more agents, like goals and orchestration."
agent 版的『苦涩教训(Salty Lesson)』(对位 Sutton 给模型的『Bitter Lesson』):「不要像你历来那样自己动手修。转而专注于那些能随更多 agent 而扩展的系统——比如目标(goals)与编排(orchestration)。」
MIRA · 批注
MIRA · 批注:Sutton 的 Bitter Lesson 是『别堆人工先验,押注算力+通用方法会赢』;这里的 Salty Lesson 把同一精神迁到 agent 时代——『别自己动手修一个个具体问题,押注能随 agent 数量扩展的系统(目标设定 + 编排)会赢』。这是对『工程师价值』的一次重定义:价值不在你亲手修了多少 bug,而在你设计的目标/编排系统能调动多少 agent。给 Gaming 的组织含义:这与 Vol.012『组织重心从谁能执行迁向谁能选对要造什么』完全咬合,并补上中间层——选对意图(offense)→设计能扩展的循环/编排(Salty Lesson)→agent 执行。三层里,纯执行最先被商品化,意图与编排是人要牢牢握住的。绩效与晋升信号也应随之调整:奖励『搭出能自动扩展的系统』,而非『加班手修问题』。

论点 05

On agents as persistent infra: "ClaudeDevs added scheduled deployments and environment variables to Claude Managed Agents, enabling recurring jobs and CLI/API auth without exposing secrets to the model; credentials are swapped at the network boundary... The common theme is a shift from 'best model' discourse toward execution control, review layers, observability, and portability."
关于 agent 作为持久基础设施:「ClaudeDevs 给 Claude Managed Agents 加了定时部署和环境变量,支持周期性任务和 CLI/API 鉴权,而不把密钥暴露给模型——凭证在网络边界处被替换……共同主题是:从『哪个模型最好』的讨论,转向执行控制、审查层、可观测性与可移植性。」
MIRA · 批注
MIRA · 批注:把这条放在 Loopcraft 收尾,是因为它是『循环』从理念落到基建的证据——当你不再 prompt 而是设计循环,循环就需要被当成持久服务来运营:能定时调度、能安全注入凭证(在网络边界换、不进模型上下文)、能观测、能换模型。注意整段的判断与 Vol.012 DEEP A『把前沿 API 当不稳定依赖、保持 portability、持续 eval』完全一致:行业话语权正从『best model』转向『execution control / review / observability / portability』。给 Gaming 的基建清单:把内部 agent 循环按『持久服务』标准建设——① 定时/事件触发调度;② 凭证在边界注入、绝不进模型上下文(安全合规底线);③ 全链路可观测(每步轨迹可回放);④ 模型可替换。这四件套是『循环时代』的运维地基。

TIKTOK GAMING · TAKE-HOME

  1. 把团队 AI 成熟度指标从『谁 prompt 写得好』迁到『谁设计的循环跑得稳、能无人值守扩展』:把『循环设计/编排』当作新的一等工程技能来识别、培养、激励(prompt 工程正被循环设计取代)。
  2. 为每条 AI 管线先问『验收能不能自动化』再决定人留不留在循环里:可自动验证环节(构建/测试/数据/批量素材)激进把人移出循环换杠杆;不可验证环节(玩法手感/数值/品味)人留在循环里换可靠性。
  3. 把自动化程度做成可调档旋钮而非开关:为每条管线定义『循环层级阶梯』与升降档触发条件(连续 N 次自动验收通过→上升一层减人工 checkpoint;M 次回归→下沉一层加回人工 review),动态校准信任。
  4. 按 Salty Lesson 重定义工程价值与绩效信号:奖励『搭出能随 agent 数量扩展的目标/编排系统』而非『加班手修一个个问题』——执行最先被商品化,意图与编排是人要握住的。
  5. 把内部 agent 循环按『持久服务』四件套建设:定时/事件触发调度 + 凭证在网络边界注入(绝不进模型上下文) + 全链路可观测可回放 + 模型可替换——这是循环时代的运维地基,也是合规底线。

论点 01

「SkillOpt 的核心想法其实很直觉:把 Skill 的 md 文件当作神经网络里的可训练参数,然后用训练神经网络的那套纪律去优化它。神经网络的权重 → Skill.md;梯度 → 基于任务轨迹的反思分析;学习率 → 每次文本编辑的幅度预算;验证集 → held-out 数据上的评分门控;epoch → 多轮迭代优化。」
(原文为中文)核心:把 Skill 的 markdown 文件当成神经网络里的可训练参数,用训练神经网络那一整套纪律来优化它——权重对应 Skill.md,梯度对应『基于任务执行轨迹的反思分析』,学习率对应『每次文本编辑的幅度预算』,验证集对应『在留出数据上的评分门控』,epoch 对应『多轮迭代优化』。
MIRA · 批注
MIRA · 批注:这是把『优化 prompt/skill』这件一直靠手感的事,第一次装上了完整的训练学科框架。它正面回答了所有做 agent 的人都头疼的问题:Skill.md 改了到底有没有变好?以前是『改改跑跑、好就留下、不好再改』,没有验证集、全凭手感;SkillOpt 把它变成有梯度(轨迹反思)、有学习率(小步编辑)、有验证集(评分门控)的可复现优化。这正是 DEEP A『设计循环』里最硬核的一个落地循环——一个自动优化 skill 文档的循环。给 Gaming 的直接价值:你们内部一定积累了大量手写的 agent skill / 系统提示(客服、QA、运营、策划助手),它们大概率从没被系统优化过。SkillOpt 给了一条可立刻试的路:用真实任务轨迹 + 自有评分集,把这些 skill 文档从『手感版』迭代成『验证过的最优版』。

论点 02

「第六步:验证门控。这是最关键的一步。候选 skill 文档不会直接生效,必须先在验证集上跑一轮评分,只有得分严格优于当前 skill 文档,才会被接受。否则这次修改直接丢弃。」
(原文为中文)六阶段管线的最后一步『验证门控』是最关键的:合并后的候选 skill 文档不会直接上线,必须先在验证集上评分,只有严格优于当前版本才被接受,否则这次修改直接丢弃。
MIRA · 批注
MIRA · 批注:验证门控是整个方法的灵魂,也是它区别于普通『让大模型帮我改改 prompt』的关键——没有评分门控的『AI 改 prompt』只是换了种手感,有门控才叫优化。它和 DEEP A『循环时代要可观测、要验收门』、Vol.012『自建 golden set 把评判权握在自己手里』、Vol.011『黄金基准集侦测静默漂移』是同一根主线:eval/验证集是这一切的地基。没有自己的评分集,你既不能优化 skill、也不能侦测模型漂移、也不能放心自动 merge。给 Gaming 的优先级排序:在追逐任何 agent 自动化之前,先建『贴业务的可验证评分集』——它是 SkillOpt 式优化、自动验收、漂移侦测三件事共用的底座,投入产出比最高。

论点 03

「最终产物是一个通常只有 300 到 2000 token 的 best_skill.md 文件。部署的时候,直接把这个文件作为系统指令喂给模型就行了,不需要任何额外的模型调用,推理成本为零。」
(原文为中文)最终产物是一个通常仅 300–2000 token 的 best_skill.md;部署时直接作为系统指令喂给模型即可,无需任何额外模型调用,推理成本为零。
MIRA · 批注
MIRA · 批注:这条点出了它在工程经济上的杀伤力——优化成本(多轮 epoch、优化器模型)是一次性的训练期开销,产物却是一个零推理成本的小 markdown。对比微调:不用动权重、不用 GPU 训练管线、不增加每次推理的成本,却能拿到接近『为你的任务定制』的效果。给 Gaming 的成本判断:在『提示工程(免费但靠手感)』和『微调(强但贵且重)』之间,SkillOpt 这类『skill 文档优化』开辟了第三条性价比极高的路——尤其适合任务边界清晰、有评分集、又不值得专门微调的中等场景(客服话术、特定品类出包检查、运营文案规范)。优先在这类场景试点。

论点 04
