EDITORIAL · 编辑卷首语

Vol.010 我们测了 Fable 5 的能力,Vol.011 记录了它『静默护栏』点燃的信任与治理之争。当争议沉淀,本卷把问题推到更根本的一层:在一个模型能力可以被训到 SOTA、又会被商品化的世界里,什么是模型永远学不会的?Sarah Guo(Conviction)经 Latent Space 给出最锋利的回答——应用靠『把公司私域现实整理成模型可操作的样子』赢得它在『不可训练角落(the untrainable corner)』里的位置,这种翻译永不结束、贴着客户、难以复制;而最难的『offense / 选择一开始要造什么』模型根本帮不上忙——它会做你指给它的任何事,却无法告诉你什么值得指,你无法对它做 benchmark,所以你无法训练它。一句话定调了本卷:『也许意图(intent)是比算力更稀缺的输入。』这从数学上回答了 Vol.009 起一直悬着的问题:『把 judgment 留给人类』不是怀旧,而是因为 intent 根本不在模型的可优化空间里。

与之形成本卷最重要张力的是 Logan Kilpatrick(掌管 Google AI Studio 与 Gemini API)的反向断言:『模型会吃掉 harness。』他说『模型』已不再等于权重,而是权重加上不断被吞并进来的脚手架构成的扩张系统;今天人人争造的 agent harness,其 alpha 大约只有 12 个月保质期,会被模型消化、上收为原生能力,然后 alpha 转移到别处。两篇并读,本卷的核心论断浮现并修正了 Vol.007 起的 harness-first 主线:会被吃掉的是『通用脚手架』,吃不掉的恰恰是 Sarah Guo 的『不可训练角落』——私域翻译、客户侧集成、intent。所以真正要囤的长期资产不是『我们造了个 harness』,而是 harness 之上/之外那层:私域数据结构、可审计操作日志、领域工具。第三篇给了活体样本:Every 的 Kieran 把 Slack 反馈做成『自己变成 PR』的 AI 工厂——定时例程读 Slack、自造 Rifrack 工具把反馈采集成比视频更富信息的结构化证据、隔夜跑 2-4 小时、CI 绿了自动 merge——这正是『把私域现实翻译给模型』的工程落地,也提醒了自动验收门的边界:可 CI 验证的能自动 merge,玩法手感/数值/美术品味这些不可训练角落必须留人工。

论点 01

"An application earns its place in the untrainable corner by doing unglamorous work: arranging a company's private reality so a model can act on it, handing the model the tools to act, working with the customer to change the reality of its workforce. A company that brings the translation is tough to copy – and the translation never ends. Integration and maintenance run as long as the relationship does, won by teams that put domain-specialized engineers and tools next to the customer."
「一个应用赢得它在『不可训练角落』里的位置,靠的是不光鲜的活儿:把一家公司的私域现实整理成模型可以据以行动的样子、把行动工具交到模型手里、与客户一起改变其员工队伍的现实。带来这种『翻译』的公司很难被复制——而翻译永无止境。集成和维护与客户关系一样长久,由那些把领域专精的工程师和工具部署在客户身边的团队赢得。」
MIRA · 批注
MIRA · 批注:这是本卷的定盘星,也直接回答了 Vol.007→011 一直追的那条主线『模型越强,人/应用的护城河在哪』。Sarah Guo 的回答极其具体:moat 不在模型,而在『把私域现实翻译成模型可操作形态』这件永不结束的脏活。注意它和 Vol.011『可审计的 harness 是 moat』是同一枚硬币的两面——Vol.011 讲『你能控制和审计的那层』,这里讲『你贴着客户、把现实整理给模型的那层』。给 Gaming 的直接含义:不要把资源压在『追平模型能力』上(那是 model labs 的战场、且会被商品化),要压在『把你独有的私域现实(玩家行为、运营数据、内容管线、买量与合规约束)整理成 agent 可直接操作的结构 + 工具』上。这层越脏、越贴近业务、越需要领域工程师陪跑,就越不可复制。

"The most cited benchmark score of the year is a map of territory about to be worthless, and a notice of who is about to lose the right to say what counts as good."
「本年度被引用最多的那个 benchmark 分数,是一张『即将变得一文不值的疆域地图』,同时也是一份『谁即将失去定义何为好的权力』的通告。」
MIRA · 批注
MIRA · 批注:这句配着上下文读才有杀伤力——Anthropic 之所以在 Fable 发布时抢着采用 FrontierCode 这类可验证 benchmark,正因为旧 benchmark 一旦被攻克,定义『什么算好』的话语权就要易手。对应 Vol.011『selective capability release』:谁掌握『评判标准』,谁就掌握隐性权力。给 Gaming 的处方:① 不要用『行业通用 benchmark 分』来定义你们的 AI 是否够好——那张地图正在贬值,且评判权不在你手里;② 自建『贴合你业务的可验证评测集(golden set)』,用你自己的成功标准(留存、出包质量、合规通过率、玩家满意度)来定义『何为好』,把评判权握在自己手里。这与 Vol.011 的『黄金基准集侦测静默漂移』是同一套基建,只是这里强调它还是『话语权资产』。

论点 03

"Even harder is offense, choosing what to build in the first place... The model is no help there. It will do whatever you point it at and can't tell you what's worth pointing it at, and you can't benchmark that, so you can't train it... Maybe intent is an even scarcer input than compute."
「更难的是进攻——一开始到底选择去造什么……在这件事上模型帮不上忙。它会做你指给它的任何事,却无法告诉你什么才值得去指;而你无法对它做 benchmark,所以你无法训练它……也许意图(intent)是比算力更稀缺的输入。」
MIRA · 批注
MIRA · 批注:这是整卷的标题来源,也是对『判断该不该自动化』这个跨卷悬案最干净的收口。Sarah Guo 把不可训练的东西精确定位到『offense / 选择做什么』:模型是无限的执行力,但方向(intent)它给不了,且原理上无法被 benchmark、无法被训练。这正面回答了 Vol.009 起一直悬而未决的问题——为什么『把 judgment 留给人类』不是怀旧而是结构必然:因为 intent 在数学上就不在模型的可优化空间里。给 Gaming 的组织含义:既然执行力正在被商品化、意图成为最稀缺要素,组织的人才与流程重心应从『谁能执行』迁向『谁能选对要造什么』。具体动作:把『选题/立项判断力』当作一等能力来识别、保护、激励(对应 Vol.011『表达意图是可训练工程素养』,但这里更进一步——选什么意图本身不可训练,只能靠人的品味与一线洞察)。这也是为什么贴近玩家、贴近一线的 PM/策划比任何时候都更值钱。

论点 04

"Silent degradation of AI R&D help dominated the discourse... this creates an unverifiable gap between observed and actual model capability, undermines reproducibility, and damages trust... A second-order lesson repeated by multiple practitioners: treat frontier APIs as unstable dependencies, maintain model portability, and verify outputs continuously with evals and harnesses (@dbreunig, @omarsar0, @yacineMTB)."
「对 AI 研发帮助的『静默降质』主导了讨论……它在『观测到的能力』与『真实能力』之间制造了一道无法验证的缝隙,破坏可复现性、损害信任……多位从业者反复强调的二阶教训:把前沿 API 当作不稳定的依赖来对待,保持模型可移植性,并用 evals 和 harness 持续验证输出(@dbreunig、@omarsar0、@yacineMTB)。」
MIRA · 批注
MIRA · 批注:这是 Vol.011『ladder-pulling / 静默护栏』争议沉淀一天后,社区收敛出的、最可操作的工程结论,值得作为本卷与上卷的接续记录。注意措辞已从『道德愤怒』转为『依赖管理』:把前沿 API 当『不稳定依赖』,保持可移植性,持续用 eval+harness 验证。还有一条新增的企业约束被点名——30 天留存、部分场景无 opt-out,直接排除零留存环境与部分欧洲地区(@GergelyOrosz/@scaling01)。给 Gaming 的落地:① 架构上把每个闭源前沿模型视作可替换的不稳定依赖,关键链路保持 model portability(双供应商 + 抽象层);② 合规上把『数据留存/ZDR/地域』作为选型硬约束,出海尤其要先过这一关;③ 持续 eval 不是锦上添花而是侦测供应商静默漂移的唯一手段。这条与 DEEP B『模型吃掉 harness』并读会产生张力——见下一篇。

论点 05

"Agent Arena showed #1 overall with especially large margins in confirmed task success and user praise, albeit weaker steerability... Fable 5 is plausibly state-of-the-art for many agentic coding tasks, but trust and product constraints are materially affecting adoption."
「Agent Arena 显示其总体第一,在『确认任务成功率』和『用户好评』上领先优势尤其大,尽管可操控性(steerability)更弱……Fable 5 对许多 agentic 编码任务大概率是 SOTA,但信任与产品约束正在实质性影响其被采用。」
MIRA · 批注
MIRA · 批注:把这条放在 DEEP A 收尾,是为了给『不可训练角落』提供一个反证锚点——能力(task success)和可操控性(steerability)是两个维度,Fable 5 在前者登顶、后者反而更弱。这恰好印证 Sarah Guo 的命题:纯能力可以被训到 SOTA 并被复制/商品化,但『让模型按你的私域意图精确行动(steerability + 私域翻译)』才是难复制的角落,且它正在成为采用与否的真正瓶颈。给 Gaming 的判断:选型时不要被『总榜第一』迷惑,要单独评估『在你的私域任务上的可操控性』——能不能稳定地按你的约束、口径、风格行动,比峰值能力更决定它能不能进生产链路。这也再次说明:把私域现实翻译给模型(DEEP A 论点 1)是采用价值的核心,不是附属工程。

TIKTOK GAMING · TAKE-HOME

  1. 把资源从『追平模型能力』转向『不可训练角落』:把你独有的私域现实(玩家行为/运营数据/内容管线/买量与合规约束)整理成 agent 可直接操作的结构 + 工具,这层越脏、越贴业务、越需领域工程师陪跑,就越不可复制(承接 Vol.011 harness-is-moat)。
  2. 自建『贴业务的可验证评测集(golden set)』定义『何为好』:用留存/出包质量/合规通过率/玩家满意度等自有成功标准评判 AI,别用正在贬值、且评判权不在你手的行业通用 benchmark——评测集既是质量基建也是话语权资产。
  3. 组织重心从『谁能执行』迁向『谁能选对要造什么』:intent/offense 不可 benchmark、不可训练,只能靠人的品味与一线洞察;把『选题/立项判断力』当一等能力识别、保护、激励,贴近玩家的 PM/策划比任何时候更值钱。
  4. 把每个闭源前沿模型当『不稳定依赖』:关键链路保持 model portability(双供应商 + 抽象层)、持续 eval 侦测静默漂移;把数据留存/ZDR/地域作为选型硬约束,出海先过合规这一关。
  5. 选型看『私域任务上的可操控性(steerability)』而非总榜峰值:能否稳定按你的约束/口径/风格行动,比 task-success 第一更决定能否进生产链路——可操控性弱的模型留给可容忍漂移的离线重活。

论点 01

"What we have historically thought of as the model is not the model anymore. Like when I think two years ago when LLMs were popular, the model was actually just a set of weights... [now] it's actually not just the weights anymore, it's like an entire expanding sprawling system that's built around the weights."
「我们历史上认为的『模型』,已经不再是那个模型了。我想想两年前 LLM 刚火的时候,模型其实就是一组权重……(现在)它已经不只是权重了,而是一整个围绕权重不断扩张、蔓延的系统。」
MIRA · 批注
MIRA · 批注:Logan 重新定义了『模型』的边界——它不再等于权重,而是『权重 + 持续吞并进来的脚手架』构成的扩张系统。这是理解整篇的前提,也和 DEEP A 形成本卷最重要的一组张力:Sarah Guo 说 moat 在『模型学不会的私域翻译』,Logan 说『模型的边界在不断外扩、吃掉越来越多原本属于应用层的东西』。两者其实可以统一——会被吃掉的是『通用 scaffolding』,吃不掉的是『贴客户的私域现实翻译』。给 Gaming 的判断框架:对任何一项你正在自建的 AI 工程,先问一句『这是通用脚手架(会被模型吃掉)还是私域翻译(吃不掉)』,据此决定是自建还是等模型原生能力。

论点 02

"The scaffolding is oftentimes a couple of steps ahead of what is baked directly into the model, and then what ends up happening is the model eats that scaffolding and it becomes part of the native model system. There's still value in having the external scaffolding in certain cases."
「脚手架往往比『直接烘焙进模型里的东西』领先几步,然后最终发生的是:模型吃掉那层脚手架,它变成原生模型系统的一部分。在某些情况下,保留外部脚手架仍然有价值。」
MIRA · 批注
MIRA · 批注:这条给出了节奏感——scaffolding 永远领先模型『几步』,但模型会持续追上并吞并。这意味着自建脚手架不是没价值,而是它的价值有时效:你靠它领先的那『几步』是真实窗口期,但不要把长期 moat 押在会被吞并的那部分上。给 Gaming 的操作:把自研 AI 工程显式分两类管理——(a)『窗口期能力』:吃到当下领先红利,但预设它 12 个月内会被模型原生化,不做重投资、不追求长期锁定;(b)『结构性资产』:私域数据、可审计日志、客户侧集成、领域工具,这些是模型吃不掉的,值得长期重投。最忌讳的是把(a)当(b)来投。

论点 03

"Everyone's like 'we got to go build a harness and the harness is where the alpha is' and I think that perhaps won't be true, at least in the way we think of the harness today, in 12 months. The models will have digested a bunch of that. It'll be upstreamed into the model and the alpha will be somewhere else now — it won't be in trying to spin your own harness because the model just does it natively."
「现在每个人都在说『我们得去造一个 harness,alpha 就在 harness 里』——我认为这大概不会成立,至少不会以我们今天理解 harness 的方式,在 12 个月后还成立。模型会把其中很大一部分消化掉,上收进模型本身,而 alpha 会转移到别处——它不会再在『自己造 harness』里,因为模型会原生地做这件事。」
MIRA · 批注
MIRA · 批注:这是对 Vol.007 起就贯穿的『harness-first』主线最强的反向声音,必须严肃对待——它没有否定 harness 的当下价值,而是给了它一个 12 个月的保质期警告。把它和 DEEP A 并读,本卷的核心论断浮现:『通用 agent harness』的 alpha 会被模型吃掉并转移,但『alpha 转移去的别处』正是 Sarah Guo 的『不可训练角落(私域翻译、intent、客户侧集成)』。给 Gaming 的战略修正:不要把『我们自己造了个 agent harness』当成长期护城河来宣传和重投;harness 是吃当下红利的工具,真正要囤的长期资产是 harness 之上/之外那层——私域数据结构、可审计操作日志、领域工具、客户侧集成。这也微调了前几卷的 harness-first 表述:是『私域翻译 + 可审计层 first』,通用 harness 只是阶段性载体。

论点 04

"(On application companies building their own harnesses for flexibility / to avoid lock-in) That starts out perhaps true, but then as the model capability improves it becomes less true over time. You don't have a generalized model if it can't use another harness."
「(关于应用公司为了灵活性/避免被锁定而自建 harness)这一开始或许成立,但随着模型能力提升,它会随时间变得越来越不成立。如果一个模型不能使用另一个 harness,那它就不算通用模型。」
MIRA · 批注
MIRA · 批注:这条要和 DEEP A 论点 4(『把前沿 API 当不稳定依赖、保持可移植性』)对照着批判性地读——两者表面冲突:DEEP A 说为防锁定要自建/保持 portability,Logan 说自建 harness 的防锁定价值会随模型变强而衰减。我的判断:Logan 是模型方,立场上会淡化『自建防锁定』的价值;但他的技术论点(强模型本就能适配多 harness)成立。综合给 Gaming 的结论不是『二选一』,而是分层:portability 仍要保(DEEP A 对、尤其防静默漂移与合规),但 portability 的实现方式应从『自建厚 harness』转向『薄抽象层 + 强模型自适应』——别造一个又厚又重、维护成本高、又会被吃掉的 harness 来求 portability,那是用会贬值的资产去对冲风险。

论点 05

"For Gemini, this agentic layer being powered by the anti-gravity agent harness is an additional through line for Google that connects all of our products... Coding has proved to be the general-purpose agent harness, in addition to also working really well for coding."
「对 Gemini 而言,这个由 anti-gravity agent harness 驱动的 agentic 层,是 Google 的一条额外『主线』,把我们所有产品连起来……编码已经被证明是『通用型的 agent harness』,而不只是在编码本身上表现很好。」
MIRA · 批注
MIRA · 批注:两个值得 Gaming 记下的结构判断:① 大厂正把『agent harness』当作贯穿全产品线的『through line(主线/连接层)』——即 agent 层不是某个功能,而是连接所有产品的统一底座;② 『编码已成为通用 agent harness』——coding 不只是一个垂直能力,而是 agent 操作世界的通用接口(因为代码能调用一切)。给 Gaming 的启发:如果要在内部建 agent 底座,把它定位成『连接所有内部工具/产品的 through line』而非孤立功能,且以『代码/可执行接口』作为 agent 操作内部系统的通用层——让内部系统都暴露可被 agent 调用的代码级接口,这比给每个工具单独做 agent 包装更可扩展,也与 Vol.011『从软件内部用自然语言改软件』一脉相承。

TIKTOK GAMING · TAKE-HOME

  1. 给每项自研 AI 工程贴标签:『通用脚手架(会被模型吃掉,预设 12 个月保质期,只吃窗口红利不重投)』vs『私域翻译/结构性资产(模型吃不掉,长期重投)』——最忌把前者当后者投资。
  2. 不要把『我们自建了 agent harness』当长期护城河宣传:harness 是吃当下红利的阶段性载体,真正要囤的是 harness 之上/之外的私域数据结构、可审计操作日志、领域工具、客户侧集成。
  3. portability 仍要保(防静默漂移 + 合规),但实现方式从『自建厚 harness』转向『薄抽象层 + 强模型自适应』——别用又厚又会贬值的 harness 去对冲锁定风险。

MIRA · 批注
MIRA · 批注:两个可操作的设计点。① 批量化是为了让人的 review 可管理——不是把 17 个反馈变成 17 个 PR 让人逐个看,而是聚合成可批量审阅的形态。这呼应 Vol.011『AI 提效后人与人对齐/review 的权重上升』:产出量上来后,瓶颈从『做』转到『审』,必须把 review 本身设计得可规模化。② compound step(犯错后沉淀为不再犯)是把『纠错』变成『可累积的私域资产』——错误被结构化沉淀进系统,下次自动规避。给 Gaming:建 agent 管线时,把『人类 review 的可管理性』和『错误的可累积沉淀』当作一等设计目标,而非事后补丁——前者决定能否扩规模,后者决定系统会不会越用越聪明(这又是一类模型吃不掉的私域资产)。

  4. 把『人类 review 的可管理性』(批量聚合而非逐条 PR)和『错误的可累积沉淀』(compound:犯错后结构化沉淀、下次自动规避)当一等设计目标——前者决定能否扩规模,后者是模型吃不掉的私域资产。
