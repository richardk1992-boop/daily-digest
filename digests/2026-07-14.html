The Loop Is the Moat — 当前沿模型趋同,护城河退守到编排与循环层

本期一句话 · TL;DR

又是安静的一天,唯一的重磅是 Lenny『How I AI』三集连播,却意外汇成同一句反直觉的结论:模型本身已经不是护城河了。Claire 拆解 harness(把 agent 包起来的代码)——她的判断是通用 agent 现在最好用来『编排』专用 harness,而不是亲自干每件事;Alex Finn 用一队本地机器 7×24 跑 AI,把『无限推理』而非 ROI 作为理由,并直言循环(loop)是最后的竞争壁垒;GPT-5.6 Sol 评测里最刺眼的一句是『超级聪明和真能交付之间的鸿沟是真实存在的』。三集共同把价值从『用哪个模型』推向『怎么包、怎么循环、怎么按任务匹配模型』——这是 Vol.039『价值逃向人侧』在工程侧的镜像:机器侧趋同后,差异回到编排层。

带着这 3 个问题读 · 思考题

  1. 如果你现在把团队最强的前沿模型换成第二强的,你的产出质量会掉多少?如果答案是『掉不了多少』,那说明你的护城河根本不在模型上,而在你有没有把它包进一个稳定的 harness、跑进一个持续的 loop——你在这一层的投入,配得上它的重要性吗?
  2. Alex 的规则是『本地模型当 BDR、Claude Code 当 closer』:让便宜模型每 20 分钟扫一遍出量,让前沿模型一天判一次出判断。你现在是不是反过来了——用最贵的模型干最琐碎、最该被廉价循环吞掉的活,同时又舍不得为『判断环节』留出真正贵的算力?
  3. 『超级聪明和真能交付之间的鸿沟是真实的』——你选型时到底在优化哪一个?如果你一直在追榜单上最聪明的模型,却发现真正能拿给 stakeholder 看的产物来自那个『taste 分更高但不是最聪明』的模型,你的评测标准是不是该从『智商』换成『交付品味』?

▎ 深度分析 · 1 篇

HOW I AI · 编排层

循环即护城河:harness、本地机队与 Sol 评测,三集同证『模型不再是差异』

Lenny's Newsletter · How I AI(Claire Vo × Alex Finn 三集连播) · 原文
信号 ●● · 颠覆 ●● · 可操作 ●● · 独特 ●○ · 时效 ●● · 8/10
三集互不相干的『How I AI』——什么是 harness、如何 7×24 跑本地 AI、GPT-5.6 Sol 评测——却收束到同一个反直觉结论:前沿模型本身已经不再是护城河,真正的差异退守到了编排层:你怎么把模型包进 harness、怎么让它在 loop 里持续跑、怎么按任务智能度匹配模型。
承重论据 · 为什么成立

harness 就是『包住 agent 的代码』,而通用 agent 现在最好的用法是去编排专用 harness,而不是亲自干每件事。

Claire 给 harness 祛魅:它不神秘,就是你为让 AI 更擅长某个具体活而写的代码——Cursor 是复杂 harness,Claude Code 是复杂 harness,你的可以只是八个文件加一个终端界面。判断何时该建:一个活既有确定的部分(固定步骤、固定工具),又有不确定的部分(AI 自己找根因、写报告)。而她真正的认知转弯是这句:『通用 agent 现在更适合用来编排专用 harness,而不是自己做每一份工作』——给受约束的 agent 一个专用 harness,比给强大 agent 一个开放提示框,产出更稳定。这把 Vol.036『harness 才是产品』推进了一步:harness 不只是产品,它是通用智能的调度对象。

本地 AI 的理由不是 ROI,是『无限推理』;而让机队真正有用的技能,是按模型智能度分配任务。

Alex Finn 用 Mac Studio、DGX Spark、RTX 5090 组了一支 7×24 的本地机队。他算得很清楚:$10000 的 Mac Studio 对比 $20 的 ChatGPT 订阅,只有当你让 agent 一天跑 24 小时时才不疯——那种规模下云 API 会迅速变贵,而本地模型持续跑打开了原本经济上不成立的用例(每 20 分钟一次的安全扫描、代码审查、社交信号监控)。更关键的是分工原则:GLM 5.2 是 Opus 级但极慢,派给耐延迟的深度活;Qwen 3.6 快且够用,派去读 Twitter 抓产品信号;Ornith 1.0(带 RL 的 Qwen 编码微调)在每个 eval 上都赢过 Qwen。『到处都用最聪明的模型』是浪费——把模型智能度匹配到任务复杂度,才是让常驻 AI 在经济上说得通的那门手艺。

『本地模型当 BDR、Claude Code 当 closer』,以及『超级聪明 ≠ 真能交付』——价值从智商转向交付品味。

Alex 的混合范式最能落地:本地模型(GLM 5.2)每 20 分钟扫一遍代码、把发现丢进 Markdown;Claude Code 一天读一次那份报告、判断哪些是真问题值得修。廉价模型出量,前沿模型出判断——若反过来让 Claude Code 每 20 分钟跑一次,一个月要烧掉数千美元。而 Claire 的 GPT-5.6 评测给了这条线最锋利的注脚:她的五项基准里,Sol 拿了最高的 taste 分,尽管 Fable『理论上更聪明』——『超级聪明和真能交付之间的鸿沟是真实的』。选型标准从『谁最聪明』变成了『谁的产物我真敢拿给 stakeholder 看』。

一个张力 · 它没说的
这三集是播客回顾,不是一手研究或可复现的实验:样本是 Claire 和 Alex 两个人的主观工作流,GPT-5.6 的模型名(Sol / Fable / Terra / Sonnet 5)与评测口径都带强烈个人色彩(70% 人评 / 30% 机器),外推到你的场景要打折。Alex『循环是最后的护城河』本身也可能是自我合理化——Claire 当场就给了反解:大多数人对 loop 含糊其辞不是因为它是机密,而是因为他们的 loop 很无聊,含糊比具体更能博互动。此外『本地机队』的前提是你有能力也有意愿维护五台机器和多 agent 冗余(三 Hermes + 两 OpenClaw,常有三个坏掉靠另两个修),这对绝大多数团队是负资产而非护城河。但即便如此,核心信号依然成立:当谁都能接入前沿模型,你在编排层——harness、loop、模型路由——的功夫,才是别人抄不走的部分。
对 TikTok Gaming 意味着什么
对 TikTok Gaming 而言,这条主线是 Vol.039『价值逃向人侧的判断与克制』在工程侧的镜像:那边讲机器趋同后价值逃向人的判断,这边讲机器趋同后差异退守到编排层。可操作的版本有三条。其一,别再把预算和注意力押在『追最新最强的模型』上——做个诚实的测试:把你产品里最强的模型换成第二强的,若产出质量掉得不多,说明护城河根本不在模型层,该把工程投入挪到 harness 和 loop 的稳定性上。其二,照抄 Alex 的分层经济学:识别那些『高频、可容忍粗糙、出量为主』的活(内容安全扫描、玩家反馈聚类、社群信号监控),用便宜/本地模型每隔一段跑一遍出量,只把『判断环节』留给前沿模型一天判一次——不要用最贵的模型干最该被廉价循环吞掉的活。其三,把选型标准从榜单智商换成『交付品味』:像 Claire 那样为你的真实产物(PRD、原型、审查报告)建一套自己的五项基准,按『敢不敢拿给 stakeholder 看』打分,而不是按谁在公开 benchmark 上更聪明。
值得记住的原话

“General-purpose agents are now better used to orchestrate specialized harnesses than to do every job themselves.”

通用 agent 现在更适合用来编排专用 harness,而不是自己去做每一份工作。

“That gap between 'hyper-intelligent' and 'actually ships' is real.”

『超级聪明』和『真能交付』之间的那道鸿沟,是真实存在的。
