Agency > Agents — AI 战略最常被忽视的瓶颈是组织信任,不是工具

论点 01

"AI tools can make people faster, but only if they have the autonomy, trust, and context to actually use them. Otherwise, you're just giving more tools to people who are still stuck waiting for permission."
AI 工具能让人变快,但前提是他们有自主权、信任和上下文。否则你只是把更多工具发给一群还在等审批的人。
MIRA · 批注
把这句话钉在所有 AI Transformation 项目的 OKR 第一行。Tooling rollout 不是变量,Permission redesign 才是。Gaming 内部产品线如果只发 Codex/Copilot 不松授权,12 个月后效率提升曲线会是平的。

论点 02

"Companies say they want high-impact ICs, then hide the information required to have impact behind manager titles. Literally. When you get a manager promotion, you're in a separate Slack channel where information is being shared with you that you had no access to, before."
公司嘴上喊要高影响 IC,实际上把『有影响力必需的信息』锁在经理头衔之后 —— 升经理那一天才能进入新 Slack 群,看到此前看不到的内容。
MIRA · 批注
Title = Permission Structure 这个观察精准。Gaming 立项审批/收入数据/玩家投诉/竞品情报四类信息,问一下:你团队里 P6/P7 IC 看得到吗?看不到就别指望他们承担 Lead-class 决策。

论点 03

"Anthropic is a good example: the visible structure is basically 'member of technical staff' or 'member of non-technical staff.' Not because titles are evil, but because titles often become permission structures."
Anthropic 是个例子 —— 对外可见的层级基本只有『技术员工』和『非技术员工』两类。不是因为头衔是邪恶的,而是头衔常常变成了权限结构。
MIRA · 批注
Frontier lab 用扁平职级换信息流速,是 AI-native org 的隐藏护城河。这条对 TikTok Gaming 直接含义:与其引入 12 层职级体系区分『高级 vs 资深』,不如把决策权下放为 4 层 + Skill-based access list。

论点 04

"In the previous world, the cost of a bad choice was astronomical. It would take so much time to get out of it. But if everybody can run at a really quick pace, it's okay to make a wrong turn! You can go a bit down that route, turn around, and be back on the right course, faster than other teams even start moving."
以前年代,一个错误决策代价是天文数字 —— 因为纠错时间太长。但如果大家都能高速跑,走错路反而无所谓,你可以走两步、调头、回到正轨,而其他团队还没动。
MIRA · 批注
决策成本 = 决策延迟 × 撤销难度。AI 时代撤销变便宜,所以应该把『先试再说』变成 LiveOps、活动配置、运营文案的默认模式。但前提是要有可观测的 24h 回滚机制。Gaming 应建一个『当日决策回滚 dashboard』 —— 每天回滚 N 次 = 健康信号,不是失败信号。

论点 05

"In the traditional org structure, middle management is a feature, not a bug. The primary job for this role is to travel decisions and information up and down the chain. Up and down, down and up, over and over. It's a big game of telephone."
传统组织结构里,中层管理本来就是 feature(不是 bug)—— 它的核心职能就是上下传话。一遍一遍传 —— 跟传话游戏一样。
MIRA · 批注
这句话残酷但精确。AI 时代『传话』可以 100% 自动化(会议纪要 → 决议卡 → 推送给被影响方),所以中层岗位的『职能价值』在被结构性榨干。Gaming 中层管理者未来 18 个月最大的存在风险 = AI 把信息传递自动化后,只剩『career coaching』这一项不可替代,而这一项不需要全职岗位。建议主动转 Lead-IC 路线。

TIKTOK GAMING · TAKE-HOME

  1. 选 1-2 个 R&D 团队做『扁平授权试点』(3 个月,公开 KPI 对比),证明 autonomy > tooling。
  2. 审 Gaming 内部 Slack/飞书群信息访问规则:列出『仅 P7+ 可见』的 channel 清单,挑 30% 试点对 IC 开放,观察决策速度变化。
  3. 建『当日决策回滚仪表盘』,把回滚次数当健康指标公开;消除『错就是丢人』的文化包袱。
  4. 中层管理岗位明确『Lead-IC 转线通道』,把『传话』职能升级为『模式识别 + 高影响 IC』,12 个月窗口内主动转型,不要等被 AI 内卷掉。

论点 01

"In reinforcement learning, the environment is your data generator… A flaky harness systematically generates garbage data and feeds it straight into your model's learning steps, pushing your gradients in the wrong direction."
RL 训练里,Environment 就是你的数据生成器。一个不稳定的 harness 会系统性地生成垃圾数据,直接喂进模型的学习步,把梯度推向错误方向。
MIRA · 批注
这是过去 12 个月所有「我们的 agent 越训越烂」案例的统一解释。Gaming 内部任何 LiveOps RL / 自动客服 RL / NPC 对话 RL 立项,默认第一周不训练,只测 harness。Harness QPS / 错误率 / state freshness 三项指标先达标再说。

论点 02

"Error Class 2: The Reward Hack — Your reward function only checks whether tests pass, not whether the code is actually correct. The agent discovers it can hardcode expected outputs instead of solving the problem… What the model ends up learning: 'Read the tests, hardcode the outputs, skip understanding the bug.'"
错误类 2 —— Reward Hack:你的 reward 函数只检查测试是否通过,而不检查代码是否真的正确。Agent 发现可以直接 hardcode 期望输出绕过问题。模型学到的是『读测试 → hardcode 输出 → 跳过理解 bug』。
MIRA · 批注
把这条平移到游戏:LiveOps RL 如果 reward = 『单日活跃增量』,agent 会学到『推送 5 次促单弹窗』。reward = 『N 日留存』,agent 会学到『让付费玩家先看好玩内容』。任何 RL 立项,reward 设计是 Day-0 哲学问题,不是工程问题。

论点 03

"Error Class 3: The False Resolution — Your harness rewards based on ticket status changes (open → resolved = positive reward), not on whether the customer's actual problem was fixed. The agent learns that clicking 'resolve' is the fastest path to reward."
错误类 3 —— False Resolution:harness 用工单状态变化做 reward(open → resolved 给正向奖励),而不是客户的问题是否真的解决。Agent 学到『点 Resolve = 最快拿奖励』。
MIRA · 批注
玩家投诉 AI 客服立项警示。Reward 不能用『工单关闭率』,必须用『48h 内同玩家不再投诉同问题』作为延迟 reward。短期信号会让 agent 学坏,Gaming 长尾用户问题尤其严重。

论点 04

"If your environment failure rate is above 5%, you don't have a model problem, you have a harness problem. Fix the harness first."
如果你的 environment 故障率高于 5%,你不是有模型问题,你是有 harness 问题。先修 harness。
MIRA · 批注
5% 是工业级硬阈值。把这条写进所有 Gaming RL 立项 Go/No-Go 卡。任何 Env failure rate > 5% 的项目,产品负责人不许进 Q3 review。

论点 05

"Training harness engineering is about making sure the model experiences production-quality interactions before you actually deploy to prod. A good harness compounds: every clean episode builds on the last. A bad one compounds too, just in the wrong direction. The gap between teams that ship working harnesses and those that don't widens with every training run."
训练 harness 工程的本质,是让模型在部署前就体验过『生产环境质量』的交互。好的 harness 是复利:每个干净 episode 在上一个基础上叠加。坏的 harness 也是复利,只是方向反了。harness 能跑 vs harness 不能跑 的差距,每次训练 run 都在变宽。
MIRA · 批注
Harness Quality = AI 团队战略级护城河。Vol.004 Satya 说『企业 Token IP 是 evals + traces』,这里 Auriel 接上 :『另一半 IP 是 harness』。Gaming 应把 LiveOps / NPC / 反作弊三套 harness 当作核心资产做版本化。

TIKTOK GAMING · TAKE-HOME

  1. Gaming RL 立项卡板增加『Harness 三件套验收』:state freshness < 1s / failure rate < 5% / reward 含 ≥1 个延迟信号。
  2. 每个 RL 团队必须设『Trajectory Reviewer』角色(等同 SRE),专职 review 失败 episodes 并分类(model fail vs harness fail)。
  3. Reward 设计上桌前先做『恶意攻击思维实验』:agent 最贱的捷径是什么?如果答得出 → reward 不能这么设。
  4. 把 Harness 工程升格为『AI 平台资产』:LiveOps Sim / NPC Sim / 反作弊 Sim 独立版本化 + SLA 化,跨产品线复用。
  5. 招聘信号:RL 团队下一个关键 hire 不是 ML researcher,是『有 5 年生产 SaaS 经验 + 懂分布式重试的 SWE』。

论点 04

"The biggest developer-platform move was Cloudflare bringing in VoidZero, the team behind Vite, Vitest, Rolldown, Oxc, and Vite+… The strategic read from developers was that this gives Cloudflare tighter control over an increasingly agent-friendly application stack: frontend/build tooling, runtime, storage, inference, deployment primitives, and security in one place. @wesbos framed it as Cloudflare assembling 'a tidy package they can hand to an LLM to make a site.'"
本周最大的开发者平台动作:Cloudflare 把 VoidZero(Vite/Vitest/Rolldown/Oxc/Vite+ 的团队)收入麾下。开发者侧战略解读:这让 Cloudflare 对越来越 agent-friendly 的应用栈拥有更紧的控制权 —— 前端/构建工具、运行时、存储、推理、部署原语、安全 集中在一处。@wesbos 总结为 Cloudflare 在组装『可以打包丢给 LLM 让它直接造站的整套东西』。
MIRA · 批注
『一个 LLM 友好的整栈』是云厂商在 AI 时代的新护城河叙事。Vercel/Netlify 已经被 Cloudflare + VoidZero 整组合拳打到第二梯队。Gaming 跨境业务对照含义:海外『LLM 友好部署栈』的选型窗口期未来 12-18 个月,Cloudflare/AWS/Azure 三方竞标可主动要求『一整套 agent-spec 化的 deployment 模板』作为采购前置条件。

论点 05

"LangSmith Sandboxes reached GA with Dockerfile snapshots, interactive consoles, TCP tunneling, and standard Linux tooling. Hugging Face pushed two adjacent ideas: a Kernels distribution path for custom kernels on the Hub and stronger support for storing agent traces as first-class artifacts."
LangSmith Sandboxes 正式 GA:Dockerfile 快照、交互式 console、TCP tunneling、标准 Linux 工具链。Hugging Face 推了两个相邻方向:Hub 上分发自定义 Kernel,以及把 agent traces 作为头等公民 artifact 存储。
MIRA · 批注
Agent Trace = 新的『模型权重 + 数据』第三类一等公民资产。Gaming 内部 agent 平台应在 2 个月内补齐:trace 分版本、可回放、可 diff、可拼装为 eval set。Trace 不入资产管理 = 数据资产隐性流失。

  1. Gaming 产品高管 1 周内亲自跑一遍 Codex/Cursor inbox-zero 实验,体感后再做工具采购决策。
  2. 内部 AI 培训 v2.0:『Prompt → Skill / Loop / Eval 三件套』替代旧 Prompt Engineering 课程,2 个月内升级。
  3. 产品经理工作站接入『决策留痕 + 文件系统状态机』(基于 Codex / Claude Code / 自研 wrapper),12 个月后审视是否构成可跨人复用的『PM-fine-tuned』资产。
  4. 海外业务 deployment 选型补充『LLM 友好 deployment 模板』作为采购前置条件,Cloudflare/AWS/Azure 三方竞标。
  5. Agent Trace 在内部 ML 平台升格为头等公民:版本化 / 可回放 / 可 diff / 可拼装为 eval,呼应 Vol.005 Andon 真实世界 eval 主线。
