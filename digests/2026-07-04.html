本期一句话 · TL;DR

Vol.029 全行业收敛到一个词 Loop,Vol.030 集体为『人的能动性』辩护;Vol.031 是这条弧线的第三拍——AIEWF 收官日把它送上辩论台做一场诚实审判:loops 的炒作和真正 work 的东西之间,到底有没有落差?正方(Ralph Loop 作者 Geoffrey Huntley、Keycard 的 Ian Livingstone)说循环不可逆、可验证性(verifiability)才是核心;反方(HumanLayer 的 Dex Horthy、Subroutine 的 Greg Pstrucha)说炒作跑在纪律前面、该往下降一个抽象层、买再多 token 也编排不掉你的问题。Amplify 年度调查坐实了这个矛盾:95% 用 agent、89% 能写数据,却『没人搞定控制层』、40% 被成本卡住、59% 担心 AI 代码在制造长期负债。第二篇深读是 Vercel 的 Andrew Qu 给这场辩论的和解——agent 是一种新软件,答案不是全自动也不是全人工,而是『为每个任务选一个合适的反馈循环』。

带着这 3 个问题读 · 思考题

  1. loops 辩论的核心不是『循环好不好』,而是 Horthy 说的『在哪个抽象层操作』。回看你正在自动化的那条管线——你是在往上跳一层(让 agent 编排整件事),还是像 Horthy 建议的往下降一层、先在小处迭代把直觉建起来?你有没有『还没真正碰过问题就把它整条自动化』的地方?
  2. Livingstone 把可验证性(verifiability)拎成核心:一个循环只有在你能验证它的输出时,才值得去加速。你那条循环里,agent 的产出你是真的能验证,还是只是『看起来对』?你是先有 eval / 验证,还是先有吞吐量?
  3. Amplify 调查里 59% 的人担心今天的 AI 代码正在制造长期负债。你的团队用更低成本做了更多软件——但你在衡量长期可维护性,还是只在衡量速度?那笔正在累积的技术负债,现在谁在替你记账?

信号 ●● · 颠覆 ●○ · 可操作 ●● · 独特 ●● · 时效 ●● · 9/10
Vol.029 让整周收敛到『软件工厂/Loop』的共识,Vol.030 是它的反作用力(人的能动性辩护),Vol.031 则是这条弧线的第三拍——收官日主持人 Allie Howe 一句话把它送上辩论台:『loops 背后的炒作,和实践中真正 work 的东西之间,到底有没有落差?』这不是又一次为循环欢呼或反对,而是一场诚实的对质:正方说循环不可逆、可验证性才是本质;反方说炒作跑在纪律前面、真正需要的是往下降一个抽象层。Amplify 的年度调查把整场矛盾坐实成数字——能力全面起飞,控制层却没人搞定。
承重论据 · 为什么成立

正方:循环不可逆,可验证性才是核心;而且『试—学—用』本来就是软件开发的循环,问题只是能多快加速它。

Ralph Loop 作者 Geoffrey Huntley 开场就定调:『它不可逆,会一直在。我不觉得自己会回到手写代码。』Keycard CEO Ian Livingstone 给出更本质的论证——真正重要的是可验证性(verifiability),而验证可以对任何代码做,不管它是怎么产生的;并且『一个循环本就是「我试一个东西、我学到一个东西、我应用一个东西」的核心;我们谈的无非是能多快加速这个过程』。Huntley 还贡献了本卷的封面比喻——loopmaxxing 之下人的角色:『我们现在有点像火车司机了。我们的活儿,就是让火车别脱轨。』人没有离开循环,而是从『开车的』变成『守着别脱轨的』。这条正好落在 Vol.030『outer loop 是能动』的延长线上。

反方:炒作跑在纪律前面;别往上跳一个抽象层,反而该往下降一层——买再多 token 也编排不掉你的问题。

HumanLayer 的 Dex Horthy 先把立场划清:『核心不是循环好不好——Kubernetes 就建在控制循环上,但那是确定性的循环。』他真正的忧虑是『炒作正在跑赢纪律』:『我没看到证据说我们已经到了可以直接往上跳一个抽象层(让 agent 掌管写代码)的地步;真要说,我反而认为我们该往下降一层。』他反对工厂式的端到端自动化,因为那样『你永远碰不到问题本身』,主张从小处开始、用 agent 循环迭代、把直觉建起来,而不是一上来就整条自动化。Subroutine 的 Greg Pstrucha 从经济性补刀:agentic 循环的成本不可持续,你『没法靠买更多 token 把问题编排掉』。连正方 Huntley 都承认工厂『还没在市场里跑通,这是前沿思考』。

Amplify 年度调查把这场辩论坐实成数字:能力翻倍起飞,控制层却没人搞定,近六成人担心在制造长期负债。

Barr Yaron 的 2026 AI 工程师调查给了辩论一个现实底座:95% 的受访者现在用 agent(约为去年两倍),用 agent 的团队里 89% 说 agent 能写数据(去年是 52%)——『agent 不再只是读、总结、起草,它们在系统内部采取行动了。』但控制手段仍原始:人工审批和权限是仅有的两大护栏,『没有人搞定 agent 的控制层』。成本是真约束:40% 说 AI 成本经常限制他们用 AI 的野心,token 用量已是第二受关注的生产指标。最尖锐的一条:59% 的人担心今天的 AI 生成代码正在制造长期负债——实验更便宜、产量更多,和质量、可维护性并不是一回事。Anthropic 的 Mike Krieger 谈内部模型 Claude Tag(更委派、更异步、更主动)时也承认,团队正『卡在审查上,卡在人把事情想清楚的能力上』——这就是早期软件工厂在实践中的真实瓶颈。

一个张力 · 它没说的
这是一篇辩论日报,两边其实都在卖自己的书:Huntley 卖 loopmaxxing、Horthy 的 HumanLayer 卖『人在循环里』的工具,立场天然对立。但别把它读成一场势均力敌的口水战——真正有信息量的是 Horthy 那句『核心不是循环好坏,而是你在哪个抽象层操作、那个循环是不是确定性的』。Kubernetes 也是循环,但它是确定性、可验证的循环;今天的争议在于把不确定的 agent 循环直接架到最高抽象层,却没有配套的验证与控制。所以正反两方其实指向同一个答案:可验证 + 确定性的环节可以放心加速(Livingstone),不可验证 + 需要直觉的环节要先降一层、把问题摸透(Horthy)。那个哭笑不得的收尾细节最能说明问题——辩论结束要举手投票,舞台灯太亮,主持和辩手都数不清有几只手举起来,一次纯粹的『人类失败』;真需要自动化的,或许是先把灯调暗这种确定性小事,而不是把整个判断层一口气交出去。
对 TikTok Gaming 意味着什么
对 TikTok Gaming,这条把三卷合成了一个完整闭环:Vol.029 让你搭工厂、把内层执行自动化;Vol.030 让你显式守住外层那个定义目标、承担责任的节点;Vol.031 则要求你在放大规模之前,诚实测一测你的循环到底 work 不 work。三条具体做法。第一,采纳 Horthy 的纪律:任何一条你打算端到端自动化的管线,先从小处迭代、在真实问题上把直觉建起来,别在还没碰过问题时就整条交给 agent——买更多 token 编排不掉一个你根本没理解的问题。第二,把可验证性当成加速的闸门(Livingstone):一个环节只有当你能独立验证它的产出时才值得让循环全速跑;所以先建 eval / 验证,再谈吞吐——没有验证的循环,跑得越快脱轨越狠。第三,盯住那个 59% 的负债信号:更便宜的实验和更多的代码不等于更好的系统;把长期可维护性、而不只是交付速度,列进你的生产指标,否则今天省下的时间会变成明天要还的技术负债。

“You can't orchestrate your problems away by buying more tokens.”

你没法靠买更多 token 把你的问题编排掉。

LATENT SPACE / AIEWF · Vercel

Vercel 的 Andrew Qu:agent 是一种新软件——给 loops 辩论的和解,答案不是全自动也不是全人工,而是『为每个任务选一个合适的反馈循环』

Latent Space · 专访 Andrew Qu(Vercel Chief of Software,MCP 库 / skills.sh / eve 框架作者) · 原文
信号 ●● · 颠覆 ●○ · 可操作 ●● · 独特 ●● · 时效 ●● · 9/10
如果深读一是把 loops 辩论摆上台对质,这一篇就是给它的和解。Vercel 的 Chief of Software Andrew Qu 提出:agent 是一种真正的新软件——它不像 web app 那样可预测,交互、界面、输出都远更动态,因此需要一套新的原语(context / tools / resumability / long-running)。而对『该全自动还是留人在循环里』这个把辩论撕成两半的问题,他给出的答案不是二选一,而是一句工程判断:『为每个任务选一个合适的反馈循环。』
承重论据 · 为什么成立

agent 是新软件,不是又一种 app:基础设施看着像,但交互/界面/输出的动态性逼你换一套原语。

Qu 直言:『我认为 agent 是一种新型软件。它们不像 web 应用那样可预测。基础设施可以长得类似,但交互、界面和输出要动态得多。』这改变了你构建它们的方式——你需要为上下文、工具、可恢复性(resumability)、长时任务准备不同的原语。Vercel 的框架 eve 正是从自家 vibe-coding 产品 v0 的一堆『纸割伤』里长出来的:切换模型/供应商、加 fallback、让运行可恢复——这些现成工具都没解决,于是被沉淀成可复用的原语再组装成 eve。他还给了一条挑选标准:适合交给 agent 的,往往是『重复但仍需要一点推理』的任务——不是固定自动化,因为系统得解读情境、决定怎么做。这正是 Vol.029『软件工厂』落到框架层的具体形态。

对 loops 辩论的正面和解:不是全自动、也不是全人工,而是为任务选一个合适的反馈循环。

面对深读一那场撕裂的辩论,Qu 给的答案冷静而可操作:『我不认为未来是全自动循环,也不认为是全程人在循环里。关键是选一个契合任务的反馈循环。』具体判据——如果任务定义清晰、你知道最终产出该长什么样,让循环一直跑到完成是合理的;而对更需要小心、更外科手术式的工程工作,你应该时不时回来检查、确保自己在正确地引导模型。这句话把 Vol.030 的『人的能动性』从一句立场翻译成了设计动作:能动性不是『永远守着整个外层』,而是『按任务的可定义性和风险,决定这条循环要不要人、在哪个点插进来』——恰好与深读一 Livingstone 的可验证性、Horthy 的『降一层』收敛到同一处。

Skill = 给模型『前向纠错』过时知识;而 web 正在分叉成两套体验——给人看的视觉版,给 agent 读的结构化版。

Qu 给了 skill 一个 Vol.030 没强调的功能:前向纠错(forward-correct)。模型常带过时信息——比如还在推荐 Vercel 几年前就弃用的 Postgres;一个 skill 可以直接告诉 agent『它已废弃』并把它导向当前方案。『在公司能审计并更新每一份旧内容之前,skill 提供了一种给模型前向纠错的办法。』这把 skill 从 Vol.030 的『被压缩的专家词汇』补上了另一半:它也是让快速变化的组织事实跑在模型陈旧训练之前的维护手段。更前瞻的一条是 agent 可读的 web:Vercel 的报告显示 bot 流量在涨、人类流量停滞,于是他们已经在做——检测到是 agent 发的请求就直接返回 Markdown,而不是逼它去解析给视觉浏览器写的 HTML;未来一份内容两套体验,人拿视觉版,agent 拿机器可读版。他的收尾很直接:『Vercel 自己正在变成一个 agent。』

一个张力 · 它没说的
要把洞察和定位分开:Qu 是 Vercel 的人,eve 框架、skills.sh、『把平台本身变成 agent』既是判断也是生意,『agent 可读的 web』这条尤其押注在 bot 流量经济学会持续这个前提上——如果 agent 访问没有转化成价值,这套双体验可能只是成本。但两个洞察不依赖它的定位也成立。其一,『为任务选反馈循环』是对深读一那场二元辩论最干净的拆解——它把『自动 vs 人工』从意识形态之争降维成一个按可定义性与风险来做的工程决定,与 Livingstone 的可验证性、Horthy 的降一层完全同构。其二,skill 作为前向纠错,正面回答了深读一里 59% 的负债焦虑的一个侧面:模型的陈旧知识本身就是一种持续负债,而 skill 是把组织的当前事实喂回循环、按住这种漂移的低成本手段。这两点绕回 Vol.028 的契合与 Vol.026 的 taste——能力商品化后,溢价停在你对『这条任务该配哪种循环、该纠正哪条过时事实』的判断上。
对 TikTok Gaming 意味着什么
对 TikTok Gaming,这条是深读一的落地补丁,把辩论变成三个可执行动作。第一,别再问『要不要全自动』——对每一条工作流单独问『它配哪种反馈循环』:定义清晰、产出可验证的(接上 Livingstone),让循环一路跑到底;模糊的、外科手术式的,就设检查点、由人来 steer。这就是深读一那场辩论的操作版答案,一条一条地判,而不是整体站队。第二,把 skill 当成前向纠错工具用:盘一遍你的产品/领域里模型最容易搞错、最过时的事实(废弃的 API、改过的口径、新的合规要求),写成 skill 把 agent 导向当前真相——这正是那批担心『长期负债』的人缺的维护纪律,模型的陈旧知识本身就是负债的一种。第三,如果你的产品有内容或 API 面向外部,认真对待 agent 可读这件事:当越来越多访问来自 agent,给它们返回结构化/Markdown 而不是给人看的 HTML,是一笔现在就值得观察、可能很快要下注的基础设施投资。
值得记住的原话

“I don't think the future is all autonomous loops, and I don't think it is all human-in-the-loop. It is about choosing a feedback cycle that fits the task.”

我不认为未来是全自动循环,也不认为是全程人在循环里。关键是为任务选一个合适的反馈循环。

“Agents are a new type of software. They are not as predictable as web applications.”

agent 是一种新型软件,它们不像 web 应用那样可预测。
