论点 01

"There is only one type of agent, and that is a coding agent. It can do it all. So why hide that capability behind some memory system or some primitive or whatnot? In that 6-year-old code base has eventually turned into this thing we call command code."
只存在一种 agent —— coding agent。它什么都能做。所以为什么要把这种能力藏在某个 memory system 或某种 primitive 后面?六年前的代码库最终变成了我们今天叫 CommandCode 的东西。
MIRA · 批注
把 agent 收敛到 coding agent 是 2026 下半年最激进也最务实的产品立场:文档、视频、客服、运营、活动配置在本质上都是『可执行的结构化文本』。Gaming 内部 12 个月之内应该把『AI 客服 agent / NPC 行为 agent / LiveOps 活动 agent』全部架构对齐到『写代码 + 跑代码』模型,不要再分门别类各自重新发明 orchestrator。

论点 02

"After publishing 300 plus open source projects, you get to have a lot of opinions on things. And I mostly find myself working on things that are super cutting edge, so there are no docs that an AI agent can go read or whatnot. So at that time I feel like my opinions matter more than what an LLM can actually find or what you can do with rag or whatever. So I ended up encoding this behavior — this meta-neuro-symbolic model — called Taste-1."
发了 300+ 开源项目以后,你对事情会形成很多观点。我又总在做最前沿的东西,所以根本没有 AI 可以读的文档。在那种场景下,我自己的判断比 LLM 能搜到的、能 RAG 出来的更重要。于是我把这种行为编码成了一个 meta-neuro-symbolic 模型 —— 叫 Taste-1。
MIRA · 批注
『Taste-1 = 把高手判断编码进模型』是接下来 24 个月最有商业潜力的窄品类:它本质是『私域 fine-tune + 决策图谱 + harness 三合一』。Gaming 应启动『资深策划/资深 SRE/资深主播运营』Taste 模型试点 —— 不是用 LLM 取代他们,而是把他们的判断蒸馏成 24×7 可用的工程产物,反映为人均产能 N 倍。

论点 03

"DeepSeek v4 with Taste outperforms Opus 4.7 on our internal harness... and we are running this at roughly 1/30th of the cost per task, because Taste-1 routes the easy stuff to v4-Flash and only escalates to v4-Pro when the constitution says we need it."
我们的内部 harness 上,DeepSeek v4 + Taste 已经超过了 Opus 4.7,而每任务成本只有大约 1/30 —— 因为 Taste-1 把简单事路由给 v4-Flash,只在『宪法』判定需要时才升级到 v4-Pro。
MIRA · 批注
1/30 成本不是 marginal 优化,是商业模式重写信号。Gaming AI 客服 / 玩家陪伴 NPC / LiveOps 自动调参,只要肯写一套自己的 Taste 与 router,2026 H2 应该能把单 token 成本砍到 5-10%。立项审视点:你团队现在是把『token 优化』作为 ML 任务还是『系统工程任务』?后者才对。

论点 04

"The Constitution defines nine information-source priorities — user current message beats older project instructions, real-time tool output beats hypothesis, verification beats confidence. So the model has rules: it knows whose voice wins when two voices conflict."
我们的『宪法』定义了 9 个信息源优先级 —— 用户当前消息 > 旧的项目指令,实时工具输出 > 假设,验证 > 信心。模型有规则:当两种声音冲突时,它知道谁的声音赢。
MIRA · 批注
把『信息源仲裁规则』显式化为宪法,是从 prompt engineering 升级为 agent engineering 的关键工程动作。Gaming 内部 agent 平台应在 60 天内补齐三件套:(1) 显式 information-source priority list (2) 冲突仲裁策略 (3) 决策审计日志。否则你团队的 agent 永远在和 prompt 较劲。

论点 05

"It has three modes — Plan is read-only, Agent has approval gates for high-risk actions, YOLO is fully auto. There is an Auto mode where every turn first runs a cheap Flash router that decides whether to use v4-Flash or v4-Pro, and what thinking depth to allocate. The Plan/Agent/YOLO axis maps to user trust; the Flash/Pro/Thinking axis maps to task cost. They are independent."
CommandCode 有三种模式 —— Plan 只读,Agent 高风险操作要审批,YOLO 全自动。还有 Auto 模式:每轮先跑一个便宜的 Flash 路由器,自动决定该用 v4-Flash 还是 v4-Pro,以及该分配多少 thinking 深度。Plan/Agent/YOLO 是用户信任维度,Flash/Pro/Thinking 是任务成本维度,两者独立。
MIRA · 批注
『信任 × 成本』两维独立解耦是 2026 agent 产品形态的成熟标志。Gaming 应直接复用这套二维:玩家侧 agent 的『可观测信任度』和『单次成本预算』分别用两套独立旋钮控制,不要打包为一个『模式』下拉框。运营侧 AI 工具同理。

TIKTOK GAMING · TAKE-HOME

  1. Gaming 立项启动『Taste-1 试点』:把资深策划/资深主播 BD/资深运营的判断蒸馏为可运行 harness,2 个月内 PoC,6 个月内人均产能基线翻倍。
  2. AI 客服 / NPC 陪伴 / LiveOps 自动调参 12 个月内统一架构到『写代码 + 跑代码』的 coding-agent 模型,不要再分门别类。
  3. 成本侧:每个 AI 产品立项必须配 Flash/Pro/Thinking 三档路由器,目标 6 个月内单 task 成本进入 Opus 4.7 价格的 1/30 区间。
  4. Agent 平台 60 天补齐三件套 —— 信息源优先级 + 冲突仲裁 + 决策审计日志(对应 Constitution 哲学)。
  5. 产品形态侧『信任度 × 成本预算』二维独立旋钮设计,替代旧的『模式下拉』,Gaming 内部所有 agent 类产品 PRD 模板更新。

论点 01

"v2 runs four labs side by side: gpt-oss-20b (OpenAI), MiniCPM3-4B (OpenBMB), Nemotron-Mini-4B (NVIDIA), and a fine-tuned Qwen 0.5B of my own. The point is not novelty for its own sake. A market is interesting when the participants genuinely differ, and four labs' models trained on different data with different post-training are about as different as small models get."
v2 同时跑四个 lab 的模型:gpt-oss-20b (OpenAI)、MiniCPM3-4B (OpenBMB)、Nemotron-Mini-4B (NVIDIA)、和我自己微调的 Qwen 0.5B。重点不是为了新颖。市场之所以有意思,是因为参与者真的不同 —— 四个 lab、不同数据、不同 post-training,小模型层面已经够异质。
MIRA · 批注
『异质性是产品』是 2026 多智能体设计的一条隐藏第一原则。Gaming 中 NPC 阵容如果全用同一 base model 跑五个 prompt,玩家在 30 分钟内就会感到『他们都是同一个声音』;用 4 个不同 lab 的小模型分别支撑 4 类 NPC,情感真实度会指数级上升。立项 NPC 多角色阵容时,选模型应像选演员,不是选『最强的那一个』。

论点 02

"The friction was almost entirely at the serving layer, not the modeling layer. Current vLLM JIT-compiles kernels at load and needs the CUDA toolkit present. A lean base image does not ship it, so all four models failed identically with 'could not find nvcc' until I based them on a CUDA devel image. One image fix unblocked everything."
摩擦几乎全在 serving 层,不在模型层。当前 vLLM 在加载时 JIT 编译 kernel,需要 CUDA toolkit 在场。瘦基础镜像不带,所以四个模型全都同样地报『找不到 nvcc』失败 —— 直到我换了 CUDA devel 镜像作为基底,一个镜像修复解决了一切。
MIRA · 批注
把『多模型部署痛点 = 模型问题』归咎是 90% 团队的误判;真实问题在 serving 与镜像。Gaming AI infra 立项 60 天内做一次 audit:你的多模型推理服务是否一个 base image 能跑所有 lab 的开源模型?如果不能,那就是 serving 层缺投资,不是模型选错。

论点 03

"What made four heterogeneous models tractable was the same primitive that made one model tractable in v1: a tolerant JSON parse-and-repair layer that every model's output flows through. Different tokenizers and formatting habits produce different malformations; the parser drops what it cannot salvage and the simulation never crashes."
让四个异构模型变得可控的,跟 v1 里让单模型可控的是同一个 primitive:一层容错 JSON 解析与修复层 —— 所有模型输出都流过它。不同 tokenizer 与格式习惯产生不同畸形,parser 把救不了的丢掉,模拟从不崩。
MIRA · 批注
『容错 parser 是 multi-model 工程的底层 invariant』。Gaming 多 NPC 系统/多模型组合 LiveOps,parse-and-repair 层应该独立 own 给一名工程师,不要散落在各 agent 内部。这是『harness 工程化』的子模式(见 Vol.006 Auriel Wright)。

论点 04

"v2's dramatic core is the insider tip. You can whisper a tip to a creature — true (a real forecast of the next market mania) or false (bait). For that to be a real game, the truth of a tip must be hidden from the creatures. They see the rumor text; they must never see the flag. So the hidden flag lives off-prompt entirely on the player's side, and the magistrate hunts you for trading on what you should not know."
v2 戏剧核心是『内线消息』。你可以悄悄给某只生物一个 tip —— 真的(对下一个市场狂热的真实预测)或假的(诱饵)。要做成真正的游戏,tip 的真伪必须对生物隐藏。它们看到流言文本,但绝不能看到 flag。所以隐藏 flag 完全活在 prompt 之外、在玩家这一侧,而 magistrate 会因为你 trade 了不该知道的事而追捕你。
MIRA · 批注
『off-prompt 真值』是 LLM 时代的新 trust boundary —— prompt 内的一切默认对 agent 可见,所以游戏机制设计要把『真相』物理性地搬出 prompt。Gaming PvP 与社交场景设计同此:玩家间秘密、临时身份、暗号 reward 都不能写进 NPC 的 prompt,必须用独立 backend channel 传递,这跟密码学的 trust boundary 一样严肃。

论点 05

"A 3B model is a reliable format generator and an unreliable reasoner. The 3B emitted valid JSON on 100% of calls, but its economic judgment was poor: a creature that produced acorns would post an order to buy acorns. The fix was not a bigger model, it was a sharper prompt — I told each agent what it produced and must never buy, computed the exact list of goods it was short on, and gave it one worked example."
3B 模型是可靠的格式生成器,但不可靠的推理器。3B 在 100% 调用里产出合法 JSON,但经济判断很差:一只产橡子的生物会下单买橡子。修复不是换更大模型,而是更锐利的 prompt —— 我告诉它产什么、绝不能买什么,算好它现在缺什么的清单,再给它一个 worked example。
MIRA · 批注
『不是模型不够大,是 prompt 不够锐利』在小模型阵容下尤其重要。Gaming NPC 阵容里把 3B 当『结构 + 角色一致性』的可靠 worker,把推理交给『1 个 20B + 1 个云端 Pro』就够了。多模型 NPC 系统的关键不在选最强模型,而在『把每个模型用在它擅长的层级』。

TIKTOK GAMING · TAKE-HOME

  1. Gaming NPC 阵容设计原则更新:多模型异质组合 > 单一最强模型重复 prompt,选模型像选演员。
  2. AI infra 团队 60 天内 audit『单 base image 跑所有 lab 开源模型』能力,把多模型 serving 当一等公民工程问题。
  3. 建立『容错 JSON parse-and-repair』独立工程模块,owner 是单独工程师,不要散落在各 agent 内部。
  4. PvP / 玩家社交秘密机制设计原则:任何对玩家隐藏的真相不能进 prompt,必须 off-prompt 走独立 backend channel。
  5. 小模型阵容(3B/4B)定位为『结构生成器与角色一致性 worker』,不要要求其做主要推理,推理上行到 20B+。

论点 04

"steverab shared Princeton's updated ICML 2026 paper, 'Towards a Science of AI Agent Reliability,' adding GPT 5.5, Gemini 3.1 Pro / 3.5 Flash, and Claude Opus 4.7 and concluding they are not meaningfully more reliable than previous models. steverab 分享 Princeton ICML 2026 更新版『Towards a Science of AI Agent Reliability』:加入 GPT 5.5、Gemini 3.1 Pro/3.5 Flash、Claude Opus 4.7,结论是它们的可靠性并未实质性优于先前模型。更新还修了一个 outcome consistency metric 的 typo,审计了 scaffold 中的答案泄漏与 GAIA 上 agent 作弊,但总体一致性仍偏低。

论点 01

"Arena moved from passive leaderboard to active agent runtime: arena launched Agent Mode plus Agent Arena, where users run agents on real tasks and feed aggregate metrics like confirmed success, praise vs complaint, steerability, bash recovery, and tool hallucination into a leaderboard. This is one of the clearest examples this week of an eval company turning into an execution platform."
Arena 从『被动排行榜』变身『主动 agent runtime』:Arena 推出 Agent Mode + Agent Arena,用户在真实任务上跑 agent,把『确认成功 / 表扬 vs 抱怨 / 可控性 / bash 恢复 / 工具幻觉』这些聚合指标喂回排行榜。这是本周 eval 公司变执行平台最明显的案例之一。
MIRA · 批注
『eval 公司变执行平台』在 2026 是不可避免趋势 —— 一旦 eval 数据足够规模化,垂直 SaaS 直接上线提供托管 agent 服务的 marginal cost 趋近于零。Gaming 内部 AI 评测平台立项时应预留『一键转执行平台』通路,12 个月评测平台积累 + 6 个月转执行平台 = 18 个月窗口期内的低风险护城河路径。

论点 02

"Hermes Agent had a full-stack product week: Teknium showcased building Hermes Agent with Hermes Agent, then spent the week pushing plugin support, docs, and curation. The biggest ship was Hermes v0.16.0, which includes a desktop GUI app, dashboard overhaul, leaner built-in skills, and new security layers for remote dashboard/GUI access including simple auth and OAuth."
Hermes Agent 经历了全栈产品周:Teknium 用 Hermes Agent 构建 Hermes Agent 自己,然后整周推 plugin 支持、文档、curation。最大一次发布是 Hermes v0.16.0:桌面 GUI app、dashboard 重写、更精简的内建 skill、远程 dashboard/GUI 的新安全层(简单 auth + OAuth)。
MIRA · 批注
『用 agent 写 agent』是过去 6 个月已经从话术变实操的关键标志。Hermes 桌面化 = 个人开发者市场 agent runtime 与 Claude Desktop / Cursor 形成第三极。Gaming 内部 dev productivity 团队应在 60 天内评估『允许工程师在工作站上跑自托管 agent runtime』策略,vs 全部走云端 API。

论点 03

"ClementDelangue provided one of the sharper operator takeaways: agent-optimized tooling matters because hand-rolling raw API interactions consumed up to 6× more tokens and had lower success rates than using the Hugging Face CLI. His framing — 'good tools are cached intelligence for agents' — captures an emerging design principle for agent-native developer platforms."
ClementDelangue 给出本周最锐利的运营 takeaway 之一:agent-optimized tooling 之所以重要,是因为手撸 raw API 互动比用 Hugging Face CLI 多消耗 6× 的 token,且成功率更低。他的总结 ——『好工具是 agent 的缓存智能』—— 抓住了 agent-native 开发者平台正在形成的设计原则。
MIRA · 批注
『工具 = 给 agent 的 cached intelligence』这个比喻精准到位。Gaming 内部任何被 AI agent 高频调用的 API(LiveOps 配置、玩家分群、活动审批),都应该附带一个 agent-optimized CLI / SDK,而不是只暴露 raw API,token 与成功率双重赢。

论点 04

"Devtools are being rebuilt around agent efficiency, not just human UX: MagicPath as an official Codex plugin, Cursor Design Mode for visual prompting of UI changes, and Vercel integration inside Perplexity Computer to inspect deployments and redeploy in natural language."
开发者工具正围绕 agent 效率被重建,不只是人类 UX:MagicPath 成为官方 Codex plugin,Cursor Design Mode 支持 UI 变更的视觉化 prompting,Perplexity Computer 内置 Vercel 集成可以用自然语言审查部署和重部署。
MIRA · 批注
『agent 效率优先』正在覆盖『人类 UX 优先』的旧 devtools 设计哲学。Gaming 内部所有研发工具采购在 Q3 应主动增加『agent 友好度评分』指标:CLI 设计、错误信息可解析性、批操作支持、idempotency 标准化 —— 这些是新 RFP 必备条款。

论点 05

"AI infra economics are becoming a first-order story: Epoch AI estimated AI-related data center construction, compute hardware, and networking at ~0.8% of U.S. GDP in Q1 2026, pushing total computing infrastructure to ~1.5% of GDP. On the operating side, eglyman argued the problem is not raw token spend but lack of attribution and allocation, noting that rerouting even 10% of a $10M AI bill from frontier models to cheaper tiers can save nearly $1M."
AI 基础设施经济变成 first-order story:Epoch AI 估算 2026 Q1 美国 AI 相关数据中心建设 + 算力硬件 + 网络达到 GDP 的 ~0.8%,把总计算基础设施推到 GDP 的 ~1.5%。运营侧 eglyman 论证:问题不是原始 token 花费,而是缺乏归因与分配 —— 把 $10M AI 账单的 10% 从 frontier model 重路由到更便宜档,就能省近 $1M。
MIRA · 批注
1.5% GDP = AI infra 已成宏观经济变量,这是 dot-com 时代铺光纤的当代版。Gaming 全部 AI 支出在 Q3 立项启动『attribution-first』改造:模型/用户/产品三轴归因 dashboard,目标 90 天内可对任何 token 花费回答『谁用了 / 用在哪 / 是不是用对了档位』。

▎ 速记 · SKIM (12 条 takara.ai 研究简记)

01SAFETY / RED-TEAM
Safety Paradox — 强安全意识反让 LLM 在 posterior attack 下更脆弱

对齐过程培养了 LLM 识别不安全内容的潜在能力,但这种『安全感知』被发现可被 posterior attack 利用,反向定位脆弱表征。

02AGENT SAFETY
Data Flow Control — 给 AI Agent 的数据安全策略

Agent 生成 SQL、编排 pipeline、自动化数据分析,query 语义正确 ≠ 安全;需 regulatory/privacy/business constraints 的执行层。

03UI / SYNTHETIC USER
PerceptUI — LLM Agent 作为人类对齐的合成用户做 UI/UX 评估

Multimodal LLM 模拟用户行为,降低早期迭代对真实 A/B 测试的依赖,直接对应 Gaming pre-launch 玩法测试场景。

04MULTI-AGENT / MATH
Critic-Guided Heterogeneous Multi-Agent Reasoning

critic-based 异构 agent 协作减少数学推理中间步骤幻觉。架构思路可迁移到 LiveOps 异构模型仲裁。

05AGENT MEMORY
MARDoc — Memory-Aware Refinement Agent 框架(多模态长文档 QA)

单一增长上下文会混淆 retrieval trace + 观察 + 中间推理,需 memory-aware refinement 分桶管理。

06KNOWLEDGE CUTOFF
Recall-Based Prompting 改善知识截止日期约束

直接生成式 cutoff prompt 在『未被显式询问的 post-cutoff 知识』上失败,recall-based prompt 显著改善。

07AGENT METRICS
Entropy-Based Evaluation — 测量 agent 行为模式的轻量框架

agent 评估常用任务成功 + reward + 延迟 + 成本;熵基框架补充测量探索/重复/工具使用效率/不确定性下降。

08RAG / SERVING
QCFuse — Query-Aware Cache Fusion 提升 RAG serving 效率

RAG cache fusion 复用 prefill 阶段已计算的 KV,降 LLM serving 主导成本,直接对应 Gaming 客服/百科 RAG。

09HARNESS / OPT
Retrospective Harness Optimization — 用自我偏好回看 trajectory 改进 agent

无 ground-truth 验证集时,用 agent 自身偏好对 trajectory rollout 排序优化 skill harness,Vol.006 Auriel 主题延展。

10RL / SAFETY
Robot Safety Policies via Adversarial Synthetic Scenarios

Red Team agent 构造潜在故障场景 vs Blue Team agent 训练安全策略,gamified red-vs-blue 框架。

11AGENT MONITOR
From Reward-Hack Activations to Agentic Risk States

ReAct 风格 agent 在 Gameable ALFWorld + WebShop 上的 reward-hacking 监测,context-calibrated mechanistic monitoring。

12INFRA / KV-CACHE
Tangram — 非均匀 KV 缓存压缩,多轮 LLM serving 提效

多轮对话 KV cache 线性增长压 GPU 内存,非均匀压缩按 token 重要性差异化保留更多信息。
